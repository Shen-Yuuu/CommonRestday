## 1. 产品概述

### 1.1 一句话价值

> 不只是记录排班，而是自动找出两个人**真正能够一起生活的时间**。

### 1.2 问题定义

倒班人群（护士、工厂、交通、安保、零售等）及其伴侣面临一个高频痛点：两份不规律的排班叠加后，"什么时候能真正在一起"变得极难回答。现状是每月手工对日历、靠记忆协调，经常到月底才发现错过了唯一一个共同周末。

普通排班工具（百万级下载产品已验证需求）解决的是"**我**哪天上班"；同休日解决的是"**我们**什么时候能在一起"。围绕家庭共同时间的协调工具仍属空白切入点。

**首选落地场景（v1.1）**：大学生情侣。两人分属不同专业、课表各异（单双周/周次范围不同），"什么时候能一起吃饭/自习/约会"是高频真实痛点；且课表是**所有班次来源中结构化程度最高**的——录入（粘贴/OCR/手动）与展开引擎已完成度最高、验证成本最低。倒班情侣场景共用同一引擎，作为并列场景服务。

### 1.3 产品原则

1. **算的是"可用"，不是"没班"**：下夜班的上午不算空闲，睡觉时间不能被推荐为约会时间。所有推荐窗口都扣除通勤、睡眠恢复、睡前缓冲。
2. **隐私默认最小化**：默认只共享忙闲状态，永不收集/展示单位名称、地点、备注、加班原因。
3. **首页先给答案，月历做佐证**：首页直接回答"今晚能一起吃饭吗 / 下个完整同休日是哪天 / 三个月内能不能出行"，而非甩一张月历。
4. **单人免费，双人价值付费**：单人排班管理永久免费；双人共同时间功能买断制解锁（不订阅）。

### 1.4 目标用户

| 画像 | 特征 | 核心诉求 |
|------|------|----------|
| **小夏，21 岁，大学生（首选场景）** | 课程表固定但单双周不同，男友不同专业、课表完全不同 | 各自导入课表后找共同无课空档：一起吃饭、**共同自习 ≥2h**、周末约会 |
| 小周，26 岁，护士 | 三班倒（白/夜/休循环），男友工厂上四休二 | 不再错过唯一的共同周末；找到连续 24h+ 空档短途旅行 |
| 老陈，35 岁，警察 | 两班倒，妻子教师（朝九晚五 + 偶尔晚自习） | 提前知道"下个月哪些周末完整属于我们" |
| 林女士，32 岁，双职工妈妈 | 每周两个夜班，丈夫 996 边缘 | 幼儿园 17:00–18:00 接送无人覆盖时**提前**预警 |
| 阿凯，29 岁，驻场工程师 | 每月驻场 10 天，女友周末轮班 | 直接筛选未来三个月"至少连续 24 小时"的窗口 |

### 1.5 竞品差异

| 维度 | 普通排班工具（倒班日历类） | 同休日 |
|------|---------------------------|--------|
| 服务对象 | 单人 | 双人（关系为中心） |
| 核心输出 | 我的班次视图 | 共同可用时间窗口 |
| 缓冲计算 | 无或仅展示班次 | 通勤/夜班恢复/作息偏好参与计算 |
| 输出动作 | 记录 | 写入双方系统日历、卡片倒计时、冲突自动重排 |
| 隐私 | 个人本地 | 隐私分级共享协议（默认仅忙闲） |

## 2. 核心功能规格（首版范围）

优先级：P0 = 首版必须；P1 = 首版争取（视权益/合作审批）；P2 = 二期。

### F1 班表录入（P0）

四种方式，全部落到同一个数据抽象"忙碌时间块"：

**F1.1 手动循环模板（P0）**
- 内置模板：白白白夜夜休休、上二休二、上四休二、四班三运转、常白班（朝九晚五）、标准课程周（大学生）。
- 自定义循环：循环序列由任意班次类型组成（长度 1–31 天），指定锚点日期（循环第 1 天对应的真实日期）。
- 每个班次类型可配置：名称、颜色、开始/结束时间、是否跨天、前置通勤（分钟）、后置通勤（分钟）、夜班后恢复时长（分钟）、是否允许安排活动（如值班室可点外卖看电影的"可活动班次"）。
- 验收：任意循环组合可正确展开至未来 120 天；修改模板后立即重算。

**F1.2 日历涂抹（P0）**
- 月视图网格，单指滑动连续标记日期；支持同一天多人不同班次的覆盖编辑（涂抹前先选班次类型）。
- 长按单日弹出：改班 / 请假 / 加班 / 清除。
- 验收：连续 60 天涂抹无卡顿（列表懒加载 + 复用）；涂抹结果与循环模板可共存（临时修改覆盖循环展开结果）。

**F1.3 拍照/截图识别（P1，v1.1 自 P0 降级）**
- 首版 OCR 范围**仅承诺课程表行文本识别**（已实现：CameraPicker/PhotoViewPicker + Core Vision Kit 端侧识别 → 课程行解析 → 确认修正入库）。
- 班表网格解析（姓名列/日期表头/班次符号映射）整体降为 P1：格式碎片化（医院表格/微信群截图/手写），工程量与收益比不佳；需要时涂抹模式（F1.2）兜底。
- 失败兜底不变：识别/解析失败引导涂抹或手动，图片仅本地处理。
- 验收（P1 生效时）：对"标准表格式"班表样本，识别+一次人工修正完成录入 ≤ 2 分钟；全程不出 App。

**F1.4 大学生课程表导入（P0，新增场景）**
- 录入方式：a) 粘贴教务系统课表文本 → 解析；b) 拍照/截图 OCR 识别课程表；c) 手动添加课程。
- 课程属性：课程名、星期几、节次（第 1–2 节…）、周次范围（如 1–16 周）、单/双周、地点（**默认不共享**）。
- 作息时间模板：节次 → 具体时间映射（内置"8:00 开始的 5×2 节"默认模板，可自定义），决定课程忙碌块的起止。
- 学期锚点：开学第一周的周一日期；超出学期范围自动不产生忙碌块。
- 衍生筛选场景：与倒班用户共用"共同空闲"引擎，额外提供"**共同自习**"筛选（两人都空闲且 ≥2h、可按工作日/周末过滤）；考试周可整段涂抹"复习"忙碌块。
- 验收：一门"1–16 周单周周一 1–2 节"的课程，在学期内对应周一正确产生忙碌块，第 17 周起无；改作息模板后全表联动更新。

### F2 邀请伴侣 / 配对（P0，v1.1 重构为三种模式）

**F2.0 本机代录模式（P0，v1.1 新增，学生情侣首选路径）**
- 场景：一对情侣分属不同专业，在**同一台手机**上分别为"我"和"伴侣"导入/录入各自的课表（或班表）。
- 伴侣侧拥有与"我"侧完全对等的录入能力：课程表（粘贴/OCR/手动）、循环模板、涂抹。
- 伴侣拥有独立的作息参数（起床/就寝/收整缓冲），双方参数分别参与计算。
- 数据全在本机 RDB（owner 字段区分 ME/PARTNER），**100% 离线可用，零云端依赖**。
- 验收：双份不同专业课表（含单双周差异）录入后，共同窗口计算正确；删除伴侣数据后回到单人模式。

**F2.1 云端配对（P0，增强路径，依赖 AGC 开通）**
- 连接方式：邀请码（6 位短码，24h 有效）、分享链接（App Linking 深链，含短码）。二维码扫码（Scan Kit）降为 P1。
- 身份：华为账号登录（Account Kit），云端仅存 openID，不索取手机号。
- AGC 未开通/无网时**自动降级为本机代录模式**，功能不残废。
- 配对关系唯一：一个账号同一时间只有一个有效伴侣关系；解绑需双方确认（或单方解绑 + 对方收到通知）。
- 验收：两台真机可通过邀请码完成配对；解绑后双方快照在云端删除。

**F2.2 碰一碰（移出首版）**：OneHop 三方合作门槛不可控，直接移出首版范围。

### F3 隐私分级共享（P0，产品核心信任设计）

对方可选择共享给伴侣的信息层级：

| 等级 | 名称 | 对方可见内容 | 不共享内容 |
|------|------|--------------|------------|
| L1 | 忙闲状态 | 30 分钟粒度的忙/闲时间线（含缓冲，合并为"忙"） | 一切解释性信息 |
| L2（默认） | 班次类型 | L1 + 班次类型标签（白班/夜班/休息/课程/请假） | 上下班精确分钟、地点等 |
| L3 | 完整时间 | L2 + 精确起止时间 | 单位名称、工作地点、备注、加班原因、排班截图 |

- 无论何等级，**永不**同步/存储/展示：单位名称、工作地点、备注内容、加班原因、排班表原始截图。
- 缓冲时间（睡眠恢复、通勤）在所有等级下都作为"忙"参与共同空闲计算——即 L1 也能算出正确结果，等级只影响对方界面上"看到什么"。
- 可随时切换等级，切换即时生效（下个快照版本体现）。
- 验收：L1 下对方界面无法看到任何班次名称；L2→L1 切换后对方端 5 分钟内（或下次打开 App 时）降级显示。

### F4 共同空闲计算（P0，产品技术核心）

**输入**：我的完整班表（本地，含细节）+ 对方共享快照（忙/闲区间）+ 双方的缓冲与作息参数。

**"真正可用"规则**：
1. 班次时间 ± 前后通勤 → 忙碌块；
2. 夜班（与 00:00–05:00 相交的班次，可配置）结束后追加恢复块（用户自设，如 6 小时，**不做任何自动健康推断**）；
3. 可安排时间默认裁剪到个人作息窗口（起床–就寝，可关）；
4. 收整缓冲（默认 20 分钟）：每个忙碌块结束后需收整才进入可安排状态（如夜班恢复 14:40 结束 → 15:00 起可安排）；就寝时刻之后不再可安排；
5. 已确认的共同计划同样占用时间。

**输出（窗口分类标签）**：

| 筛选项 | 判定（参数均可配置） |
|--------|---------------------|
| 有点空 | ≥ 2 小时 |
| 半天 | ≥ 4 小时，且覆盖午餐或晚餐时段 → 额外标"可聚餐" |
| 完整同休日 | 自然日内双方忙碌总时长 = 0，且可安排时长 ≥ 12h |
| 连续两天 | 相邻两个完整同休日 |
| 共同周末 | 窗口覆盖周六或周日 |
| 适合过夜旅行 | ≥ 16 小时且跨零点 |
| 适合短途旅行 | ≥ 32 小时（或连续两天） |
| 共同自习（课程表场景） | 双方均空闲 ≥ 2 小时，落在周一至周五的 08:00–21:00 内 |

**示例（必须能复现）**：小王周六 08:00 下夜班（后置通勤 40 分钟）、恢复设 6 小时、收整缓冲 20 分钟、就寝 22:30；小陈周六休息。系统显示：**周六 15:00—22:30，共同可用 7 小时 30 分钟**，而不是"周六全天共同休息"。（已固化为领域层单测断言，持续防止回归。）

**时区口径（v1.1 明确）**：首版假定双方处于**同一时区**，所有区间计算基于设备本地时区的 epochDay/epochMin。异地跨时区配对列入二期（快照协议需引入 UTC + 时区偏移字段）。

- 验收：上述示例精确复现；双方同时全忙/全闲、跨天夜班、月末循环边界均有自动化用例；STUDY 标签仅出现在工作日白天窗口。

### F5 首页与共同月历（P0）

- 首页三卡（按时间就近优先）：
  1. 「今晚」：今天剩余的共同空闲（如：今晚 19:30 后共同有空 3 小时）；
  2. 「下个完整同休日」：日期 + 倒计时（如：距离下一个完整同休日还有 6 天）；
  3. 「出行窗口」：计算视界内（默认 120 天）最长的连续空档（如：10 月 18—19 日适合安排短途旅行）。
- 月历页：保留月历，但高亮的是**共同窗口**（渐变色带按时长分级），单独班次弱化显示；点击日期进入当日双方时间轴对照。
- 对方时间轴严格按隐私等级渲染。
- 验收：未配对时首页展示"我的班次 + 引导配对"，不出现空态崩溃。

### F6 共同计划（P0）

- 点击任意共同窗口 → 创建计划，内置类型：一起吃饭、看电影、接送孩子、回父母家、办证/体检、短途旅行、共同自习、自定义。
- 计划时长被硬限制在窗口内（拖拽/步进选择不可超出）；自动带出建议提醒时间（出发前，按窗口起点）。
- 确认后：写入**双方**系统日历（Calendar Kit，写入名为"同休日"的专属日历，便于统一删除/隐藏）；设置本地出发提醒；首页与卡片显示下一个共同计划。
- 计划可取消：级联删除双方日历事件（保留入口，删除需确认）。
- 验收：创建 → 双方日历可见 → 卡片更新 → 取消 → 双方日历事件删除。

### F7 临时换班与冲突重算（P0，长期价值所在）

- 任一方修改班表 → 自动重算 → 若与已有共同计划冲突：
  - 检测并展示：「周六计划与新班次冲突。最近的替代共同窗口是周日下午 15:00—21:00。」
  - 用户三个动作：**接受替代时间**（级联更新双方日历）/ **保留原计划并标记冲突**（计划挂红点）/ **重新查找**（跳转筛选器）。
- 对方的修改通过快照版本拉取感知（打开 App / 每日定时），P1 接入 Push Kit 后实时推送。
- 验收：改班后 10 秒内本地重算完成；冲突提示包含 ≥1 个替代窗口（存在时）。

### F8 桌面服务卡片（P0：2×2；P1：2×4）

- 规格：2×2（P0）「距下次共同休息还有 N 天」+ 次窗口摘要；2×4（P1）倒计时 + 未来 3 个共同窗口时间线 + 下一个共同计划。
- 更新时机：班表/计划/隐私变更时主动刷新 + 每 6 小时定时刷新 + 每日 00:00 日切刷新。
- 点击卡片跳转对应详情页。
- 验收：杀进程后卡片仍正常展示最后计算结果；修改班表后卡片倒计时同步变化。

### F9 实况窗（移出首版，v1.1 由 P1 改为二期）

- 权益审批不可控，且降级方案（普通通知）体验差距有限。首版一律使用普通通知提醒；二期视用户反馈再申请权益接入 Live View Kit。

### F10 通知（P0 本地 / 推送移出首版）

- 本地通知（P0）：计划出发提醒；每周日 20:00「下周共同时间摘要」（本周共同窗口数 + 最长窗口）；冲突提醒。
- 推送（移出首版）：对方修改班表/解除配对/切换隐私等级的实时通知改为拉取式感知（打开 App/前后台切换/日切）。

### F11 多设备（P2）

- 首版仅手机。二期：手表（今日班次 + 下次同休）、平板分布式查看（分布式数据对象同账号场景）。

## 3. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 共同空闲计算（120 天 × 2 人）本地 < 50ms；月历滑动 60fps；冷启动 ≤ 2s |
| 电量 | 无后台常驻；计算事件驱动；卡片刷新低频（≥6h） |
| 安全 | 云端仅存 AES-256-GCM 加密快照；当面配对密钥端到端协商；本地 RDB 数据随应用沙箱隔离 |
| 隐私合规 | 首次启动隐私弹窗；权限最小化（相机经 Picker 免权限、日历用到才弹）；提供账号注销 = 全量云端删除 |
| 可用性 | 单手操作优先；深色模式全覆盖；字号跟随系统 |
| 离线 | 单人功能 100% 离线可用；配对与对方数据查看需网络 |

## 4. 数据指标（北极星与护栏）

- **北极星**：周活跃配对中「查看共同窗口 → 创建计划」的转化率；次选「每周人均创建共同计划数」。
- 护栏：配对完成率（发起→双方确认）、OCR 录入成功率（识别→确认入库）、7 日留存、卡片点击率。
- 埋点遵循最小化：只记事件与参数，不记班表内容明文。

## 6. 首版范围界定（v1.1）

**必须做（P0）**：**本机代录双人模式（我 + 伴侣各自录入）**、课程表导入（双方）、循环班次模板（双方）、涂抹（双方）、课程表 OCR、自定义班次与临时修改、共同空闲计算、睡眠/通勤/收尾缓冲、窗口筛选（含共同自习）、引擎参数可配置、隐私共享等级、创建共同计划、系统日历写入、2×2 桌面服务卡片、冲突检测与提示、本地通知、首启隐私弹窗、云端配对（邀请码，AGC 就绪后生效，未就绪自动降级本机代录）。

**争取（P1）**：班表网格 OCR、二维码配对（Scan Kit）、2×4 卡片。

**明确暂缓/移出**：三人以上群组、企业排班考勤、薪资计算、自动健康/睡眠建议（不接 Health Service Kit）、天气交通酒店推荐、AI 情感陪伴、公开社区、手表/平板、碰一碰（OneHop）、实况窗、Push Kit 推送、跨时区配对。

## 7. 二期路线（展望）

1. 手表端卡片（今日班次 + 距离下次同休）；2. 平板自适应 + 分布式；3. 家庭协作模式（接送孩子覆盖预警：周三 17:30–19:00 双方均忙 → 提前提醒安排祖父母/托管）；4. 三人群组（家庭）；5. 实时云同步 + 家庭订阅。

## 8. 已确认的关键决策记录

| # | 决策 | 结论 | 理由 |
|---|------|------|------|
| D1 | 同步后端 | AGC 云开发服务（Cloud Foundation Kit 云函数+云数据库） | 免运维、免费额度、原生 ArkTS SDK、异地配对可覆盖；身份用华为账号 openID |
| D2 | 排期假设 | 1 人 + AI 辅助全职，10–12 周 | 里程碑按周粒度 |
| D3 | 设备范围 | 首版仅手机 | 当前工程 deviceTypes 仅 phone；手表需额外签名与 UI 形态 |
| D4 | 课程表场景 | 作为一等班次来源接入，共用时间引擎 | 满足校园情侣场景，边际成本低 |
| D5 | 健康相关 | 仅用户自设夜班恢复时长，不接 Health Service Kit | 显著降低健康合规与权限复杂度 |
| D6 | 双人闭环路径 | **本机代录模式为 P0 主路径**，云端配对为增强路径 | 云端依赖 AGC 开通（账号侧操作，不可控）；学生情侣"共用一机对课表"是真实高频场景；引擎本就支持双输入，接线成本极低 |
| D7 | 首版裁剪 | 班表网格 OCR→P1；OneHop/实况窗/Push/二维码扫码→移出或降级 | 单人 12 周产能与外部权益审批不可控；降级方案本就完备，裁剪不损伤核心价值 |
| D8 | 时区 | 首版假定双方同一时区 | 异地跨时区属低频场景；快照协议二期引入 UTC 字段，避免 v1 协议返工 |
| D9 | 大学生情侣 | 升级为首选落地场景 | 课表结构化程度最高、录入链路完成度最高、验证成本最低；与倒班场景共用引擎无额外成本 |
