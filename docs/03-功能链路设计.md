> **v1.1 修订**：L4（班表网格 OCR）降为 P1；L6 重构为"本机代录（P0 主路径）+ 云端配对（增强路径）"；L13（实况窗）移出首版；L8 补充本机代录装配路径；新增 L11 冲突检测的具体判定口径。

## L1 首次启动与引导

```mermaid
flowchart TD
    A[启动 EntryAbility → 唯一 @Entry 壳 pages/Index] --> B{首次启动?}
    B -- 是 --> C[隐私政策弹窗 PrivacyDialog]
    C -- 同意 --> H[首页空态\n引导卡片：先记一笔班表]
    C -- 不同意并退出 --> X[terminateSelf 退出应用]
    B -- 否 --> I[恢复上次状态\n惰性校验窗口缓存]
    H --> L9
    I --> L9
    H -.用户主动点.-> F[L2 循环模板 / L3 涂抹 / L4 OCR / L5 课程表]
```

**分支/异常**：拒绝隐私政策 → `terminateSelf` 退出（未同意前全屏拦截，不可进入任何页面）；`SettingsStore` 初始化或读标记失败 → **按"未同意"处理并重弹**（宁可多问一次，不可默认放行）。
**模块**：`entryability/EntryAbility`、`pages/Index.ets`、`component/PrivacyDialog`、`data/settings/SettingsStore`（首启标记）。
> 更正：旧稿这里的"欢迎引导页 3 步说明产品价值"与"登录华为账号（仅配对前强制）"都**没有实现、也不在范围内**——首启只有隐私弹窗，之后直接进首页空态；全链路不存在账号登录节点（不接 Account Kit）。初始录入路径由首页/班表入口自己承担，不做一次性向导。

## L2 循环班表录入（手动循环）

```mermaid
flowchart TD
    A[班表页 + 新建班表] --> B[选模板\n白白夜夜休休/上二休二/上四休二/四班三运转/常白班/自定义]
```

**模块**：feature/schedule、domain/expand、data。

## L6 配对（v1.1：本机代录 P0 主路径 + 云端配对增强路径）

```mermaid
flowchart TD
    A[我的页 → 添加伴侣] --> B{选择模式}
    B -- 本机代录 P0 --> C1[为伴侣创建本机档案\nowner=PARTNER]
    C1 --> C2[伴侣课表/班表录入\n复用 L2/L3/L5 全部能力]
    C2 --> C3[设置伴侣作息参数\n起床/就寝/收整]
    C3 --> D[首页切换为 我们 模式\n触发 L8 重算]
    B -- 云端配对（当前关闭） --> E{FeatureFlags.cloudPairing?}
    E -- false：现状 CLOUD_BLOCKED --> F[入口不出现在界面上\n引导使用本机代录] --> C1
    E -- 门禁通过后 --> G[云函数 createPairing\n生成一次性凭据+深链]
    G --> H[对方扫码/系统分享/输码\njoinPairing 建立 pairId]
    H --> I[双方选择初始隐私等级\n默认 L2]
    I --> J[双方立即推送首份加密快照 L7\n长期密钥只在 HUKS 内派生与保存]
    J --> D
    D2[解绑/清除伴侣] --> D3[删除 owner=PARTNER 全部数据\n或云端级联删除]
    D3 --> D4[回到单人模式 触发 L8 重算]
```

**分支/异常**：凭据过期/已用 → 提示重新生成；一方已有伴侣关系 → 需先解绑；AGC 未配置/无网 → 云端入口灰置并引导本机代录；解绑后本地保留只读历史（可清空）。
**模块**：`feature/integration/PairingShareGateway`（扫码 + 系统分享 + 深链校验，受 `scanPairing`/`cloudPairing` 双开关）、`domain/pair`（短码/深链解析）、`data`（owner 维度）、`cloud`（仅云端模式）。
> 更正：① 这里以前写"华为账号已登录且 AGC 就绪?"——**没有账号登录这个前置**，判据是 `FeatureFlags.cloudPairing`；② "生成短码 24h 有效"改为"一次性凭据"，因为**邀请码不得直接派生长期密钥**（改造方案 §0.3），协议细节以 [pairing-protocol-v1.md](./cloud/pairing-protocol-v1.md) 为准；③ 端侧代码已落地但入口关闭，所以这条链路当前不可在真机上走通，不是"待开发"。

## L7 快照同步（隐私分级，仅云端配对模式）

```mermaid
flowchart TD
    A[触发: 班表/参数/计划/等级变更\n或 定时/启动拉取] --> B[domain 引擎生成 ScheduleSnapshot\n按 L1/L2/L3 降维序列化]
    B --> C[AES-256-GCM 加密\n密钥=配对时协商 KEK]
    C --> D[云函数 pushSnapshot\nversion+1, 云端只存密文]
    D --> E[对方端: 启动/切前台/00:00 定时\npullSnapshot sinceVersion]
    E --> F{version > 本地?}
    F -- 是 --> G[解密 → 按等级实例化\nL1 只实例化忙闲位图]
    G --> H[触发 L8 重算]
    F -- 否 --> I[忽略乱序旧包]
```

**分支/异常**：解密失败 → 卡片进 `PAIR_PENDING` + 本机一次"需要重新配对"通知；离线 → 入待同步队列，恢复网络补发（重试复用同一 `requestId` 保幂等）。
**模块**：`domain/snapshot`（位图降维与还原）、`cloud/api`（`CloudApi` + `SnapshotCrypto`）、`data`（`sync_meta` 版本号）。
> 更正：① 触发条件删掉"收到 P1 推送"——**没有 Push Kit**，只有拉取；② 整条链路受 `CLOUD_BLOCKED` 门禁，`cloudPairing=false` 时不会被走到，本图是门禁通过后的目标态；③ "指数退避 3 次"改为按协议文档的幂等重试口径（[pairing-protocol-v1.md](./cloud/pairing-protocol-v1.md) §3）。

## L8 共同空闲计算（引擎数据流）

```mermaid
flowchart TD
    A[输入① 我的班表\n模板+override+课程+计划] --> C[expand]
    B[输入② 对方快照\n忙区间(按等级)] --> D[buffer→区间归一]
    C --> D
    D --> E[merge: 双人忙区间并集→取补]
    E --> F[classify 打标\nMEAL/HALF_DAY/FULL_DAY/WEEKEND/TRIP/OVERNIGHT/STUDY]
    F --> G[写 computed_window 缓存]
    G --> H[通知 VM/卡片/冲突检查]
```

**触发时机**：L2/L3/L4/L5 保存、参数变更（通勤/恢复/作息）、L7 快照更新、L10/L11 计划变更、每日 00:00。

> v1.1：本机代录模式下，引擎装配为"我的班表（owner=ME，我的参数）+ 伴侣班表（owner=PARTNER，伴侣参数）"，两条 expand→buffer 管线分别构建忙区间后进入 merge。云端模式下伴侣忙区间来自快照解码，不二次加缓冲。

**异常**：参数非法（恢复>12h） UI 层限制；计算本身纯函数无副作用，异常即缺陷由单测兜底。
**模块**：domain 全部、data（缓存）、feature/cotime。

## L9 首页与共同月历展示

```mermaid
flowchart TD
    A[进入首页] --> B{已配对?}
    B -- 否 --> C[单人语义首页 + 引导录入]
    B -- 是 --> D[读 computed_window 缓存]
    D --> E{缓存过期?}
    E -- 是 --> F[同步执行 L8（毫秒级）] --> G
    E -- 否 --> G[渲染三卡:\n今晚/下个完整同休日/出行窗口]
    G --> H[月历页: 共同窗口色带高亮\n我的班次弱化]
    H --> I[点日期 → 当日双方时间轴对照\n按隐私等级渲染对方]
    I --> J[点窗口 → L10]
```

**分支/异常**：视界内（默认 120 天）没有任何窗口 → 空态说清"算过了、确实没有"并给可动作（放宽作息/收整参数、看更远的日子），不能和"还没录班表"共用一句文案；对方 L1 时对照轴只显示忙/闲色块，无文字。
**模块**：`feature/usecase/CommonTimeQueryService`（首页/共同时间读模型，答案优先）、`feature/performance/RecomputeExecutor`（引擎段跑在哪个线程的唯一决定点）、`entry/view/HomeView`、`entry/view/CoTimeView`。
> 更正：① 三卡口径是"今晚 / 下个完整同休日 / 出行窗口"，读的是同一个 `HomeSummary`，**不是各自再算一遍**；② "同步执行 L8"不准确——重算是否内联跑由 `RecomputeExecutor` 按采样预算决定（120 天稠密配对 P95 14.30ms 贴着 16ms 预算，≥150 天才迁移 worker）；③ 顶部 Tab 只有三个（首页/共同时间/我的），班表在「我的」侧的导航栈里，旧四 Tab 形态已退场。

## L10 创建共同计划 → 日历 → 提醒

```mermaid
flowchart TD
    A[窗口详情页\n时间轴可视化 + 时长] --> B[选计划类型\n吃饭/电影/接送孩子/回家/办事/旅行/自习/自定义]
    B --> C[命名 + 调整起止\n硬限制在窗口内]
    C --> W{Sheet 上的\n「写入系统日历」开关}
    W -- 关（可回改） --> W0[只落本机 plan 表\ncalendar_state=LOCAL_ONLY]
    W -- 开（默认） --> D{首次写日历?}
    D -- 是 --> D1[弹 READ/WRITE_CALENDAR 授权]
    D1 -- 拒绝 --> D2[仅本地创建+提醒\n下次动作会再请求]
    D1 -- 同意 & 拒绝后重试成功 --> E
    D -- 否 --> E[取/建"同休日"专属 LOCAL 日历账户\ngetCalendar 失败则 createCalendar]
    E --> F[cal.addEvent 受管写入\n不弹系统日程编辑页]
    F --> G[写 plan 表 + calendar_state=MANAGED_WRITTEN/my_event_id]
    G --> J[首页/卡片显示下一个共同计划]
    J --> K[取消计划 / 采用替代时间]
    K --> L[确认弹窗 → cal.deleteEvent + 撤提醒\nplan.status=CANCELLED → L8 重算]
    L -- 删不动 --> M[保留 my_event_id/reminder_id\ncalendar_state=CLEANUP_PENDING\n卡片「重新清理」+ 回前台补扫]
    G -.可选出口.--> X[「导出到系统日历」mgr.editEvent\n→ EXTERNAL_UNMANAGED，本应用不再自动同步]
```

**分支/异常**：能力结果（`CalendarOutcome`：`DENIED`/`UNAVAILABLE`/`FAILED`/`CANCELED`）经 `calendarStateOf` 落成 `CalendarState`（`LOCAL_ONLY`/`UNSUPPORTED`/`FAILED`），**计划照样创建成功**，重试入口在计划卡片（`canRetryCalendarSync` 给「写入日历」、`canExportToCalendar` 给「导出到系统日历」，`calendarFlow` 关档时两个都不给）；删除失败**不是记一条日志了事**——句柄留着、状态转 `CLEANUP_PENDING`，卡片给「重新清理」，`EntryAbility.onForeground` 走 `sweepPendingProjections` 自动补一次；读库时旧值经 `normalizeCalendarState` 归一（`'WRITTEN'` → `EXTERNAL_UNMANAGED`，认不出的 → `NOT_REQUESTED`）；窗口被 L11 冲突作废 → 计划进入 CONFLICT 态。
**模块**：`feature/usecase/PlanUseCase`（编排 + `calendarFlow` 回退点）、`feature/usecase/PlanProjectionCleanupService`（只清系统侧、不写库）、`feature/integration/PlanCapabilities`（日历/提醒端口的唯一持有者）、`feature/integration/CalendarGateway`、`ReminderGateway`、`feature/model/PlanFlow`（状态机与清理报告口径）。
> 更正：① **"对方也写日历"不成立**——日历写入只作用于本机，全仓没有对端写入代码，`peer_event_hint` 列也不存在；对方要不要把同一段时间记进自己的日历，是对方设备上自己创建计划、自己确认的独立动作。② 阶段 6R.1 把方向换了：**默认是专属日历的 `addEvent` 受管写入**，`editEvent` 反过来降级成「导出到系统日历」这一个出口——因为 API 26 SDK 写明 `editEvent` 之后要 `READ/WRITE_WHOLE_CALENDAR`（system_basic，普通应用拿不到）才改得动，拿它当默认就等于给取消/改期埋孤儿。"逐条创建、不批量"仍成立：写不写由用户在计划 Sheet 的开关上当面决定。③ 旧稿的"本地通知授权引导"不在这里：通知授权只在「我的」里用户亲手打开开关时才弹（`MeView` → `NotificationGateway.requestEnabled`），创建计划后不引导。

## L11 换班修改 → 重算 → 冲突处理

```mermaid
flowchart TD
    A[任一方修改班表\n涂抹改班/改模板/OCR重录] --> B[L8 重算]
    B --> C{与已有 plan 时间交叠?}
    C -- 否 --> D[正常更新展示]
    C -- 是 --> E[plan.status=CONFLICT\n查找替代窗口: 时长最接近的后续共同窗口]
    E --> F[冲突卡: 周六计划与新班次冲突\n建议: 周日 15:00—21:00]
    F --> G1[接受替代 → 本机改期\n先尽力删旧事件，再按确认路径写新事件]
    F --> G2[保留原计划 → conflict_hint.kept=true\n停止就该冲突重复发通知]
    F --> G3[重新查找 → 带筛选器的窗口列表]
    D & G1 & G2 & G3 --> H[快照同步 L7 → 对方同步感知\n当前关闭：云门禁 CLOUD_BLOCKED]
```

**分支/异常**：无替代窗口 → **不给假建议**（`altStart = 0` 时弹窗只给"取消计划"，不出现"改到替代时间"）；双方同时修改 → 以快照 version 高者为准，低者本地下一次拉取时对齐（当前档位不发生）。

**冲突判定口径（v1.1 明确）**：重算时对每个状态 OK 的计划 P：构建"排除 P 自身占用"的双方忙区间并集，若 P 的区间与之交叠 >0 分钟 → P 置 CONFLICT；替代窗口 = 满足"时长 ≥ P 时长"的最近后续共同窗口（取时长最接近者）。

**模块**：`domain/conflict/PlanConflict`（交叠判定 + 替代窗口）、`feature/usecase/ScheduleUseCase.detectAndWriteConflicts`（回写 `plan.conflict_hint`）、`entry/view/PlansView`（三个动作）、`feature/integration/NotificationGateway`（该不该吵用户一次）。
