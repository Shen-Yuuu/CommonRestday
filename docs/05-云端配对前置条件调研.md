## 0. 结论

**可行，且零成本。** 没有任何官方条款把云开发限定为企业开发者；免费档是永久档而非试用期，双人低频同步的用量离配额差 4~5 个数量级。真正需要管理的不是开发量，而是三条运维约束：**配额用尽即停、连续 6 个月无调用即回收数据、仅中国大陆区域且数据处理位置不可随意改**。

因此建议：**云端配对 + 低频快照同步回 P0；实时同步 / Push / 协同编辑仍留二期**（后者受"无服务端推送 + 每日配额按天计"双重制约，收益低）。

此前架构文档中记录的"缺 `agconnect-services.json`""需要 `FUNCTION_TYPE_*`"两个前提被本次调研推翻，见 §5.1。

超额单价（云函数）：请求 1.9378 元/百万次、内存时长 1.421 元/万 GB-s、出网流量 1.2918 元/GB。`[事实]`

CDN 单独配额、单应用可创建的云开发项目数：`[缺证据]`（未检索到对应条目）。

### 2.1 我们实际会用多少 `[推断]`

按 2 人、每月各改班表 10 次、每天打开 3 次各拉取 1 次快照估：
- 云函数 ≈ (20 次写 + 90 次读)/月 → 占月度请求配额 **0.011%**
- 云数据库写 ≈ 20 次/月、读 ≈ 180 次/月 → 远低于**按天**的 2 万/5 万
- 单份班表快照（120 天 × 若干区间，加密后 base64）≪ 2 MB 单对象上限，1 GB 存储用不到千分之一

结论：容量层面完全不需要为配额做优化，**唯一需要设计的是 §3.2 的心跳保活**。

## 3. 三条硬约束（真正会影响排期与设计的）

### 3.1 免费档"用尽即停"，不会自动扣费也不会自动扩容
`[事实]` 官方给的处置选项是"等到下个统计周期再使用，在此之前服务将不再可用"，或升级为按量付费并从余额扣款；**降级时计费资源可能被删除**。
`[事实]` 免费配额将用尽时会通过互动中心消息 + 邮件 + 短信提醒，但**消费提醒/余额不足提醒需手动开启**。

影响：云端配对是"增强路径"，主路径（本机代录）必须在云端不可用时照常工作——这一点现有 `cloud` HAR 的降级设计是对的，别改。

### 3.2 连续 6 个月无任何有效 API 调用 → 判定闲置资源，预警 30 日后回收清理
`[事实]` AGC Serverless 服务使用协议（协议版本 2026072801）：闲置资源回收覆盖云函数/云数据库/云存储。

影响：这是本产品**最容易踩**的一条。双人低频场景意味着一个寒假/一个学期不打开就可能触发。
设计要求：
1. 客户端在每次冷启动或每周定时器里保证至少一次有效云调用（`cloudFunction.call` 心跳，成本可忽略）；
2. 心跳不能只在配对状态下发——单机用户不会产生调用，但那类用户本就没有云数据可回收，可接受；
3. 快照对象必须可重建（班表真源永远在本地 RDB），**即便云端被回收也只是退回未配对状态，不丢用户数据**。这条让 §3.2 从"风险"降级为"体验损失"。

### 3.3 区域与数据处理位置
`[事实]` 端云一体化文档："云开发目前仅支持中国境内（港澳台除外），请确保项目启用的数据处理位置包含'中国'"。
`[事实]` AGC 平台整体的数据处理位置为 中国 / 德国 / 俄罗斯 / 新加坡 四选一；云函数与云数据库可访问全部已启用位置。
两份条款并列出现 → 按更严者执行：**本项目锁定"中国"，不假设海外可选**。
`[事实]` 更改默认数据处理位置或取消启用**可能自动清理云侧数据且不可恢复**。
`[事实]` 华为为"数据处理者"，开发者为"控制者"，合规责任在开发者。删除路径：控制台单条删除 / `DatabaseZone.delete` / `StorageBucket.deleteFile` / 删除整个项目；**无一键级联注销 API**，需自己实现"解除配对/清空数据"时同步删云侧记录。
机房具体名称、账号注销后清理时限：`[缺证据]`。

## 5. 技术落地要点

### 5.1 对现有认知的更正（重要）

| 旧认知 | 更正 |
|--------|------|
| 缺 `agconnect-services.json` 是"最后 30%" | **该文件名在 HarmonyOS NEXT 端云一体化全部文档中不存在**。云侧配置为 `CloudProgram/cloud-config.json`（项目/应用 ID、数据处理位置、设备类型），由 DevEco 关联云工程时生成；云数据库 schema 落在 `resources/rawfile`（缺失报 `schemaJson_ is empty`）。`[事实]` |
| `FUNCTION_TYPE_FUNCTION / FUNCTION_TYPE_OBJECT` | 属旧 AGC Server SDK 概念，`@kit.CloudFoundationKit` 的 `cloudFunction` 参数表中没有它。类型区分只在服务端 `function-config.json` 的 `functionType: 0=云函数 / 1=云对象`，**部署后不可变更**。`[事实]` |

→ 行动：`cloud/src/main/ets/CloudApi.ets` 需按新文档逐行核对（见 §6）。

### 5.2 工程结构
`[事实]` 工程根目录**只允许 `Application` 与 `CloudProgram` 两个文件夹**，否则整个工程被识别为纯端侧工程、云侧不显示。新建时只能选 `[CloudDev]Empty Ability` 模板，Device type / Enable CloudDev 不可改。
`[事实]` DevEco 向导按 **Bundle name 去 AGC 查同包名应用**——包名必须完全一致，且类型一致（AGC 上是元服务而工程是应用会报错）；游离应用须先挂到项目；团队首次需勾选云开发协议（**仅账号持有者/法务角色可签**）。

### 5.3 客户端调用
`[事实]` `cloudFunction.call(parameters)` → `Promise<FunctionResult>`；`FunctionParams = { name(必填), data, version(默认 $latest), timeout(ms), loadMode, localUrl(6.0.1(21)+，仅本地调试) }`。权限 `ohos.permission.INTERNET`、仅 Stage 模型、能力 `SystemCapability.DeviceCloudGateway.CloudFoundation`、起始版本 5.0.0(12)。错误码 201/401/1008210001/1008210009/1008211001。
`[事实]` **超时口径冲突需注意**：端侧 `timeout` 默认 70*1000ms，而云函数**同步调用最大 55s**（异步才到 1800s）→ 客户端必须显式收敛到 ≤55s，否则用户看到的是一条永远等不到服务端答复的挂起请求。
`[事实]` HTTP 触发器属性 `authFlag`（默认 true）/ `authAlgor: HDA-SYSTEM` / `authType`：`apigw-client`＝端侧网关认证（App 调用），`cloudgw-client`＝云函数互调（用错报 `mismatched authType`）。**客户端不传任何凭证**。
`[缺证据]` 调用重试策略无文档，需自己实现幂等（快照上传按 pairId+version 幂等即可）。

### 5.4 服务端与部署
`[事实]` 运行环境 **nodejs 20.x/latest**；2025-11-04 起新建云函数不再支持 Java/Python/Custom Runtime 与 API 网关触发器（存量不受影响）。入口 `handler.myHandler`，入口文件须在部署包根目录；建议 `let body = event.body ? JSON.parse(event.body) : event;`，返回 `new context.HTTPResponse(...)`。
`[事实]` 限制：包 200MB 压缩 / 400MB 解压 / 30000 文件；内存 500/1000/2000/4000MB；CPU 500–2000m；单函数超时 1~1800s（同步 ≤55s）；环境变量 ≤1000（`AGC_`、`PROJECT_CREDENTIAL` 为保留前缀）；层 ≤5 个；改配置后 10–20s 滚动生效。
`[事实]` Windows 部署路径：DevEco 右击函数目录 → `Deploy`（或右击 `cloudfunctions` 批量），状态栏到 "Deploy successfully"；AGC 控制台也可上传 zip 或用 WebIDE。**云函数彼此独立，只部署所选目录，不能 `import '../other'`** → 公共代码要么复制，要么走云对象。依赖须落在本函数 `node_modules`（`package.json` dependencies + Sync Now / npm install）。冷启动耗时数字 `[缺证据]`。

### 5.5 云数据库（存快照的地方）
`[事实]` 端侧可**直连读写**（新增对象类型 → 新增存储区 → 引入对象类型文件 → 初始化访问 → 查询/写入/删除），谓词支持链式过滤+排序+限条数+分页，缓存模式支持侦听实时同步 → **可按 pairId 查对方快照**。
`[事实]` 硬上限：单对象 2MB；端侧单次查询结果 ≤5MB 且 ≤1000 条；云侧/端侧存储区各 **4 个**（超 4 部署失败）；对象类型 128；字段 128（≤100 个 String）；端侧侦听器 ≤16。
`[事实]` 安全规则形如 `match: /databases/{db}/objecttype/{ot}/key/{key} { allow read, write: if <cond> }`，条件可用 `request.auth.uid`、`request.auth.token.*`、`resource.data.<字段>`，多条 match/allow 任一为 true 即放行；权限不足报 `2001015:permission denied`；`fieldType` 部署后不可本地修改。
`[推断]` "仅两台配对设备可读"可表达为 `if request.auth.uid == resource.data.ownerUid || request.auth.uid == resource.data.peerUid`。
`[事实]` **关键约束：全程加密的字段在安全规则中恒为 null** → `pairId` / `ownerUid` 必须**明文**存，只有班表载荷加密。这与 `SnapshotCrypto` 现有"密钥由邀请码派生、载荷 AES"的设计兼容，但对象模型要留明文字段。

### 5.6 调试
`[事实]` 签名只能用**关联注册应用自动签名**或**手动签名**，用错报 `hmos auth app doesn't have permission`。
`[事实]` 模拟器自 6.0.0(20) Beta5 起支持：需在模拟器触发一次接口，从日志取 `clouddevelopproxy.debugToken` **注册到 AGC**；否则 401（签名校验失败）/ 403（凭据未注册或绑错应用，改后等 30 分钟）。
`[事实]` 本地联调：DevEco 端云一体化工程可把本地函数跑在 `http://localhost:18090`（`localUrl` 参数，部署后不可用）。
