## 一页纸摘要

**做什么**：一款 HarmonyOS 原生 App。两个人各自录入班表（循环模板 / 日历涂抹 / 拍照 OCR / 大学生课程表），
App 在本地计算"扣除睡眠、通勤、恢复时间后**真正可用**的共同空闲窗口"，并把答案按"今晚有空几小时 /
下个完整同休日 / 适合出行的连续空档"直接回答给用户；共同计划先保存在本机，系统日历集成走**应用专属「同休日」日历的受管写入**（创建时逐条经计划 Sheet 的「写入系统日历」开关确认，改期与取消由本应用自动同步），`editEvent` 只作为"导出到系统日历"的可选出口、导出后不再由本应用代管；班次变化时自动重算并给出冲突原因与替代时间；桌面 2×2 服务卡片与首页同源，
常驻给出"一大一次"两行结论。

**目标用户**：护士/医生与家属、工厂倒班、民航铁路公交、警务消防安保、零售餐饮酒店、一方倒班一方正常班的情侣/夫妻、接送孩子的双职工家庭、**大学生情侣（课程表场景）**。

**技术底座**（HarmonyOS NEXT，API 26 / SDK 26.0.0，`deviceTypes` 只声明 phone）：

| 能力 | 用到的 Kit | 备注 |
|------|-----------|------|
| 班表 OCR 识别 | Core Vision Kit（端侧离线） | 无需联网；`CameraPicker` / `PhotoViewPicker` 取图 |
| 写入系统日历 | Calendar Kit | 默认用 `getCalendar`/`createCalendar` + `addEvent` 写进应用专属的「同休日」日历（普通 `WRITE_CALENDAR` 就够，改期/取消删得动）；`editEvent` 仅作「导出到系统日历」，导出后本应用不再自动同步 |
| 桌面服务卡片 | Form Kit（ArkTS 卡片） | **只有 2×2 一个规格**（`form_config.json` `supportDimensions: ["2*2"]`），只从桌面添加 |
| 提醒与本地通知 | Notification Kit + reminderAgent | 精确提醒是**默认关闭的开关项**；每周共同时间摘要同理（opt-in） |
| 扫码与系统分享配对 | Scan Kit / Share Kit | 端侧已实现，但入口受 `FeatureFlags.scanPairing = false` 关闭（真机验证 + 云门禁前不出现在界面上） |
| 云端配对与快照交换 | Cloud Foundation Kit（AGC 云函数+云数据库） | **当前关闭**：Task 0.4 门禁 `CLOUD_BLOCKED`；端云配置是 `cloud-config.json`，**不存在 `agconnect-services.json`**（05 §5） |
| 本地存储与计算 | ArkData（RDB / Preferences）、纯本地算法 | RDB 是事实源；计算在开发机上 120 天稠密配对 P95 14.30ms（16ms 预算内） |
| 无障碍与适老化 | AccessibilityKit / UIDesignKit | 长辈模式、2.0× 字号、减少动效、读屏语义是发布门禁项 |

**明确不做**（改造方案 §0.3 与 05/06 调研的结论，别再顺手加回来）：Live View 实况窗、OneHop 碰一碰、
Push Kit 实时同步、三人群组、实时协作、企业考勤与薪资、自动健康建议、手表/平板形态。

**首版边界**：两人配对 ✅（P0 主路径是**本机代录**对方班表，100% 离线）；三人群组 / 企业考勤 / 薪资 /
自动健康建议 / 天气酒店推荐 / AI 陪伴 / 社区 ❌。单人使用永久免费，双人共同时间功能买断。

## 已确认的关键决策

1. **同步后端**：华为 AGC 云开发（Cloud Foundation Kit 云函数 + 云数据库），云侧只存加密快照；
   **登录身份不接 Account Kit**——全仓没有 `@kit.AccountKit` 依赖，配对关系由本机生成的配对标识承载，
   且云端链路整体受 `CLOUD_BLOCKED` 门禁关闭（05 §1、`docs/validation/clouddev-api26-spike.md`）。
   当面配对（二维码/系统分享）与异地配对都还没到可发布状态。
2. **长期密钥**：必须由 HUKS 托管，不得写入 Preferences、源码、二维码或日志；**禁止**用邀请码派生长期密钥。
   门禁未过之前，云端配对保持关闭，不允许"先上线再补安全"。
3. **数据事实源**：本机 RDB。云端失败、扫码不可用、日历被拒绝，都不得阻断本地录入与计算。
4. **导航形态**：**三个底部入口**（首页 / 共同时间 / 我的），班表收纳进「我的」侧的导航栈目的地；
   旧四 Tab / 五 Tab 形态已退场（03 与 04 里描述 5 Tab 的段落属历史记录）。
5. **资源假设**：1 名开发者 + AI 辅助；P0 范围按 ≤30 人日、纯本地、零 AI 接口费用裁剪。
6. **设备范围**：首版仅手机（`deviceTypes: phone`），折叠屏/平板只按容器宽度做响应式，不声明多设备形态。
7. **新增场景**：大学生课程表作为一等班次来源接入（课程 = 固定忙碌块，支持周次范围/单双周/节次模板），
   并衍生"共同自习/无课空档"筛选场景。
