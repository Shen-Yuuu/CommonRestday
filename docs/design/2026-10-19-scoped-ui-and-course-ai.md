# 两人份：局部升级与设计建议

日期：2026-10-19，Asia/Shanghai。依据用户五项明确要求；前三项及相册导入入口实施，其余界面只给建议。

## 本轮实现

1. Dock 使用 HDS 标准 BottomTabBarStyle / TabBarSymbol，保留同族的线框与实心图标；开启 IMMERSIVE / ADAPTIVE、adaptToHandedness 与 thermoCtrl。移除自绘选中底块和触摸拦截，使选中与拖动走系统路径。DockFx 爱心粒子保留，透明命中让出页签触摸，原有前后台、减少动效与不可见时停止逻辑不变。公开 API 接入完整不代表可复刻每款系统应用的私有表现，具体形变仍受设备、系统、算力和温控影响。
2. 首页“今天”：左侧开始时间、竖向连接与空心点、结束时间；右侧标题与类型说明。保留跨天日期、24:00、前三条及展开收起、读屏完整范围。其他主卡、字体与配色不重新设计。
3. 现有顶部 #FFF0E7 保留，纵向 180° 渐变经 #FFF0F3 到 #FBE4EE；深色沿原紫色顶部经 #2B203B 到 #362335，保持深色场景，不铺亮粉。页头渐隐端点仍匹配顶部 RGB，背景固定在根节点。
4. “课程表导入”增加“从图片导入”，提供相册与拍照入口，并完整保留我/TA 归属。进入图片页自动打开对应系统选择器；返回导入页重新读取课程列表。原项目已有 OcrCourse 与端侧识别 API，本次接通入口并补齐流程。

## 图片识别的实际范围

PhotoViewPicker 只读取用户选择的图片，不增加全相册读取或相机权限。使用授权 URI 打开文件描述符，再解码为 RGBA_8888 PixelMap，长边上限 4096，调用 Core Vision Kit 的 textRecognition。所有成功、失败和迟到返回路径释放 PixelMap、ImageSource、文件和模型资源。

文字可对照图片修改。图片解析要求明确星期、节次与周次，不套用手工录入的默认第1-2节/1-16周；全角数字与常见横线做兼容，不连续节次和周次提示分行。修改文字后清除旧解析与核对状态。保存只处理通过项，需用户核对，保留单双周，防止重复提交；失败保留草稿。

当前实现是端侧 OCR 与逐行解析，**不是任意网格课表的自动结构化理解**。网格里的星期列头、纵向节次、合并单元格和课程备注仍可能需要用户补全。课表图片不上传；没有实现云端请求、部署或付费模型接入。

## 建议的 AI 方案

| 方案 | 优点 | 对本项目的局限 | 建议 |
| --- | --- | --- | --- |
| 端侧 OCR + 本地解析 | 图片留在设备；不增加云端推理调用；能离线核对 | 字符识别不等于理解网格，当前逐行解析需要完整字段 | 当前默认入口 |
| 端侧问答模型整理 OCR 文本 | 可在支持的设备上整理文本 | SDK 的 QuestionInfo 是文本输入，不能把它当作直接读取任意课表图像的通用视觉模型；机型、版本与效果需实测 | 可选研究，不作为全部设备必经路径 |
| 云端视觉语言模型 | 可将图片、文字位置、星期列与节次行一起交给模型解释 | 网络、时延、推理成本和上传告知；仍可能产生错误字段 | 复杂网格的可选增强 |

建议采用“端侧优先，复杂课表可选云端增强”的架构。下一阶段先利用 OCR 返回的文字外框和坐标建立星期列、节次行及单元格关系；无法确定的项保留为待核对。需要云端时，由用户主动选择，上传必要图片区域和 OCR 坐标，通过服务端代理调用视觉模型；API 密钥不放在 App。输出受限 JSON，严格校验星期 1–7、节次和周次范围、单双周与来源位置，未知字段不补猜。所有路径汇合到同一个可编辑核对界面，不直接写库。

“混合方案最适合本项目”是依据隐私、兼容性、成本与识别目标作出的工程建议，不是已测得的准确率结论。模型供应商、价格与区域未确定，不虚构免费额度或固定费用。云端视觉模型提升复杂网格解析的潜力，仍需同一组真实课表样本对比后选择。

主要资料：

- [华为通用文字识别指南](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/core-vision-text-recognition)，API 输入、外框坐标与资源处理另核对当前本机 SDK。
- [华为端侧问答模型 API](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/dataaugmentation-localchatmodel-api)，本机 API 参考的 QuestionInfo.content 为 string。
- [华为云图像理解接口](https://support.huaweicloud.com/model-call-modelarts/model-call-modelarts-0003.html)，支持图文输入；这里只作为云端增强可行性依据，没有部署该服务。

## 审美升级建议：先保留，再统一

本次使用 Impeccable 的原生 Operate / polish / craft-floor 原则。用户指定的 design-taste-frontend-v2-experimental 明确排除原生移动 App，只取其“先审视、保留品牌、控制形状与颜色、验证可读性”的通用方法，不套用网站营销排版、Web 库或装饰动画。参数取 DESIGN_VARIANCE=3、MOTION_INTENSITY=3、VISUAL_DENSITY=5，表示保留既有结构与真实信息，新增改动克制；不改变已确认角色与爱心粒子。

当前品牌 #FF7EA5，圆润字体链，普通卡 28/14vp、主卡 30/16vp，首页/共同/我的三页签。可爱与粉色是已确认身份，不建议全换为极简模板。

以下**尚未实施**，建议逐项比较，而非再次整页改版：

1. **先修字的层级与对比。** 保留圆润页名和首页共同时间展示字；普通答案正文减少极粗字重，辅助说明保持13fp、正文16fp。亮粉背景上的白色小字先核对对比，优先改为深莓字，或仅把操作按钮背景加深，避免将整张主卡变成深玫红。
2. **主卡、普通卡、浮层分工。** 首页只有共同时间卡承载较强色彩；日程与设置维持清楚的实底。玻璃重点保留给 Dock 和确实覆盖内容的浮层，不把每张信息卡都做成相同重量的模糊玻璃。
3. **减少重复强调。** 首页三个快速答案的粉点、虚线和粗字可以一次只减一种，比较实拍后决定。先试细实线与清楚箭头，不删掉真实依据或过期状态。不要同时换字体、圆角和配色，使反馈难以定位。
4. **统一内部圆角和留白。** 外卡保留现有贴纸感，内部按钮/输入框采用较小的一档圆角；标签保持更小。建议测试16vp卡内边距、12vp同组间距，减少普通设置入口的重复标题；热区继续至少44vp，长辈模式沿用其现有更大热区。
5. **可爱来自现有角色与反馈。** 布布咻咻保持既有造型和动作边界；不增加密集图案、常驻漂浮动画或无意义徽标。粉色、奶黄和蓝色中，双方和安排类型的语义不能被统一玫粉覆盖。

建议下一轮只试第1和第3项，在同一真实数据、同一模拟器尺寸下做前后截图；满意后再推进设置分组与圆角。当前没有对这些建议作视觉已验收的承诺。
