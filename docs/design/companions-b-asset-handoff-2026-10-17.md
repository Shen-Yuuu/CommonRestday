# B 探头气泡：第二阶段素材交付要求

当前正式应用已使用用户选定合成图实现第一阶段整体呼吸和连击捏压。接下来缺少的是**匹配此图的分层资产**，不是新的造型提案。不要重新用几何图形拼出另一对角色。

**最新进度：** 同日后续已按确认造型完成混合格式分层与四段叙事接线，详见 `companions-layer-map-2026-10-17.md`。下面的 15 SVG 清单保留为原设计交付参照，不表示当前实现仍缺表情，也不表示本次交付是全矢量。

## 2026-10-17 用户补充：保持造型，表情与动作开放

“保持一致”指同一角色的脸型、耳朵结构、五官绘制语言、描边和配色一致，**不要求保持原图神态、视线或动作**。
允许补出短身体与爪子、改变姿态；不改成长毛、另一种眼睛风格或另一种头脸轮廓。兔子的折耳与竖耳、小熊圆耳和小额毛仍是识别点。

新动作校对稿：`docs/prototype/assets/companions-identity-expressions-review-2026-10-17.png`。
它是内置图像编辑工具基于原图生成的三组动作探索，**不是分层资产、不是逐帧动画**。
此前改变脸型、眼睛与毛发感的生成稿已被用户否定，不进入应用。
校对稿仍有裁切底边残片，不能直接作为最终透明资源使用。

随后用户确认校对稿造型一致，基于此图衍生三份干净透明 PNG：`bubu_peek.png`、`xiuxiu_peek.png`、`xiuxiu_sleep.png`。
三份已接入正式确认框、计划弹窗和空状态，旧 SVG 保留但不再引用；不能把这三份合成图当作下述 15 个独立图层。

页头现采用标题同行底对齐，备注另起一行；角色热区为 44vp 高，实际绘制区域最高 44vp。
后续的小尺寸预览应按 112×44 / 100×44 校验，而不是把图对齐到标题加备注的整体底边。

## 必须是可叠放的分层，不是贴着分层名称的合成图

1. 布布：`bubu-body.svg`、`bubu-ear.svg`、`bubu-paw.svg`、`bubu-face-0.svg` 至 `bubu-face-3.svg`。
2. 休休：`xiuxiu-body.svg`、`xiuxiu-ear-left.svg`、`xiuxiu-ear-right.svg`、`xiuxiu-paw-left.svg`、`xiuxiu-face-0.svg` 至 `xiuxiu-face-3.svg`。
3. 一张装配图及浅/深背景 112×56、100×56 实际显示预览。
4. 标注每个角色的摆放坐标、缩放比例、耳根轴点、颈部轴点、爪子默认位置，以及爪爪试探时两爪保留 4vp 间距的关键帧。

同一角色的所有图层须共享 `viewBox="0 0 120 120"` 和坐标，不得逐层紧裁后各自缩放填满。身体层不能再包含已独立的脸部、耳朵或爪子，否则运动时会露出重复部件。脸部层只画五官，不画另一张白色脸；白兔身体本身当然允许白色填充。

清晰描边、真正透明、无影无底板、无嵌入位图、无脚本/SMIL。交付文件可沿用文档中的连字符名，进入 HarmonyOS media 资源时由开发映射为下划线命名。

## 需要先在装配预览里确认

- 造型是否仍是用户选定的前兔后熊，而不是两只并排全身角色。
- 八套表情是否可无位移切换；避免默认脸与变体叠着显示。
- 耳根旋转和身体轻靠是否露缝；爪子出现时是否仍无手臂拼接感。
- 眯眼、好奇、困倦等差异在真实小尺寸下是否可辨，不仅在放大图里好看。

音效属于后续阶段。若交付三份音效，请附来源/授权证明和实际格式，不使用来源不明下载素材。播放速率与系统静音/媒体音量策略须以实际 SDK 能力验证，不能把设计稿数值直接视为平台保证。
