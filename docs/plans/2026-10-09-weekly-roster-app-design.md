# 周班表 App 实施设计

> 2026-10-10 后续批准的计算与页面调整见 [周班表页面一致性](2026-10-10-roster-page-consistency-design.md)：未安排不占用时间，不再整日加入 UNKNOWN 忙碌；常用班次移至标题栏右侧。以下保留初次设计记录。

用户于 2026-10-09 批准独立 HTML 原型用于实际 App，另明确取消日程管理中的“临时调整”入口。

## 约束

- 周班表按真实日期保存，一日多个班次，每个班次多个时段；休息与未安排分开。
- 常用班次应用后保存时间快照，编辑或删除常用班次不更改已保存的新周班表。
- 保存当前周不会默认重复；复制／周重复必须明确目标与保留／替换／合并策略，检查跨日实际工作重叠。通勤／恢复冲突采用告知确认，不静默拒绝或改动共同计划。
- “＋日程”打开个人安排／工作排班选择。日期可选，个人安排无需双方确认，进入今日时间轴和忙闲计算，并按现有共享等级同步。
- 未安排仅在用户启用工作排班后保守屏蔽共同空闲；纯课程／个人日程用户无需填写空班表。
- 老循环与单日覆盖继续兼容读取，不删除、不自动重写；明确日期记录优先。旧循环存在时未修改日期保留旧规则结果，页面告知。
- 移除“临时调整”菜单，但保留周历点日与“＋日程 → 工作排班”修改日期的能力，二者统一新编辑组件。
- 不更改配对协议或部署云模型。仅新增本地 JSON 数据契约，存在已使用的 sync_meta 中，使用 owner 专属键；损坏数据须报读失败不能当空表覆盖。
- 本次不清数据，不安装模拟器，验证离线测试及 debug 构建。设备视觉与双端同步实测交由用户。

## 数据与计算

domain 新增 ShiftSegment、RosterDay（epochDay/status/entries）、PersonalEntry 和 WeeklyScheduleState；MySchedule 可选携带 datedDays、personalEntries、weeklyMode。现有 ShiftType 可选 segments，旧单段模型不变。

feature 的 WeeklyRosterService 通过 ScheduleRepo 的 meta 键读写 owner 状态，由串行队列保证读改写一致。保存新日期前装配邻接日、课程、个人日程和计划，实际工作重叠阻止写入，其余冲突明示，事务性写入后仅一次重算及广播。保存后重算失败与写失败分开反馈。

引擎按日期记录覆盖旧循环实例，分段调用既有通勤／恢复管线，个人安排独立 PERSONAL 标签。未知日期使用 UNKNOWN 标签保守参与计算，展示不称作工作。快照复用现有加密忙区间，无须新增远端模型。

## UI

新 WeeklyRosterView 用七枚日期按钮与七行日期票签；当前周草稿单独保存，复制页限定周范围。旧 CycleEditor 路由改为周班表承载，避免遗留深链失效。ScheduleHub 首屏改周班表，管理页只保留周班表、常用班次、课程表入口。

DayShiftSheet 改为同日多班、分段快照编辑；默认保存到日期，在 WeeklyRosterView 中提供草稿回调。首页 ScheduleEntrySheet 用自适应底部弹窗，个人时间和日期使用系统选择器。ScheduleEditor 保留原生自定义颜色入口，新增分段设置，标题改常用班次。
