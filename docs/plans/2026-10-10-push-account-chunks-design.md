# Push 服务账号分段配置

用户已确认：完整 JSON 精简后仍超过控制台输入限制，直接实施每段不超过 512 字符的环境变量读取，兼容原完整 JSON，并重建 worker。真实密钥只由用户本地处理、填入云端；本次不读取密钥、不登录或部署。

配置协议：单变量 `FORTWO_PUSH_SERVICE_ACCOUNT` 与分段方式互斥。分段使用 `FORTWO_PUSH_SERVICE_ACCOUNT_PARTS=N` 和 `_1` 至 `_N`，N 为 1–32，每段为 1–512 字符，拼接 JSON 至多 16384 UTF-8 字节。缺段、额外段、无计数、有计数但仍有非空单变量和不合法 JSON/字段均拒绝；不回退旧凭据。按顺序拼接原始文本，保留 PEM 的 JSON 换行转义。

worker 若收到 context.env 中的账号配置，先清除上次注入的账号字段再安装本次配置，避免热实例用旧片段填补本次缺段。未收到 context 账号配置时沿用平台 process.env。

本地 PowerShell 工具只读取用户指定文件、取四个必需字段并生成分段；默认只显示变量名/长度，显式选择某段或完整环境 JSON 时才复制到剪贴板。不得默认输出凭据、写入仓库或上传。

服务账号配置读取放在独立模块；构建 worker 包时显式包含该模块。只同步此次涉及文件到两个既有云项目，保留其他用户改动。SDK 项目凭据继续依赖平台注入；不让用户手动创建系统保留的 PROJECT_CREDENTIAL。若平台无注入，另行处理，不能用 Push 私钥代替。

验证：真实 Server SDK 类型检查和 ES2020/ES5 合约回归，分段签名/互斥/缺段/超长/重复热调用测试；仅以生成的测试 RSA 密钥验证工具分段，无真实密钥。ZIP 内容与源文件同源，无凭据。
