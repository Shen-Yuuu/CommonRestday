# 沉浸背景与刷新效率设计

用户已确认：保持现有布局与同步规则，只优化实现。

## 两个独立改动面

1. 沉浸背景：统一为根背景的绘制区域延伸 SYSTEM TOP/BOTTOM，不忽略布局安全区、不隐藏系统栏、不改变键盘避让。Index、Navigation/目的地及独立路由页均须覆盖；渐变、深色资源继续沿用 DesignTokens。
2. 刷新效率：展示查询只读取本机/伴侣有效缓存；本地保存使用缓存重算并沿用合并推送。启动/配对完成/日切及用户下拉继续拉取云数据。刷新仅合并同一写入边界内的并发读，不缓存已完成的读结果。

云快照网络等待移到 RECOMPUTE_QUEUE 外：独立 SNAPSHOT_PULL_QUEUE 保持信封/游标更新顺序；等待完成后才进入计算锁，重新读取最新输入。缓存空/过期时页面的兜底计算使用缓存，不另发一趟网络请求。网络与解密返回后核对配对 ID/配对态，阻止旧连接的回包污染新连接。

## 共同计划

- 一次 context 验证生成只能被同一 context 对象消费一次的校验许可；identityFor 仍读取认证凭据、检查 UID、会话代次、密钥可用性。许可不跨操作复用，无长期 TTL 缓存。直接调用、复制 context、第二次调用均重新获取 capabilities。
- 每次 read/mutate/requestStatus/registerPush 云端仍执行身份与有效成员校验；服务端与密钥协议不改。
- apply 比较 sharedPlanActivity 的旧/新投影，仅实际时间占用变化才重算；状态/标题变化落库后另发共享计划数据广播，更新列表与待确认提示。
- 重算失败保留 dirty 标记，后续手动刷新即使版本不变也补算；不为此重发云端写操作。
- 并发 refresh 共享一趟；mutation 进入队列前撤销共享读许可，修改后发起的新读不能复用修改前的读。队列、事务、确认、冲突校验、持久化 requestId、失败暂停与手动重试保持不变。

## 验证

离线行为测试覆盖请求计数、重复刷新、写入边界、失败恢复、状态变化广播、确认/取消重算、直接调用的完整校验及身份/代次变化拒绝。源代码检查覆盖各路由背景安全区与本地只读/保存路径。完整 closed/open 验证与 Debug 构建。

LatestReadQueue 合并同一轮 UI 广播读数，查询进行中的新变化只安排一次最新后续读；LatestLanding 仍在发起时失效旧落地许可。组件退出撤销未开始读数。

只报告确定的调用数量变化；未做真实 AGC/双机计时，不宣称毫秒数或速度倍数。无需云端重新部署或清除手机数据。
