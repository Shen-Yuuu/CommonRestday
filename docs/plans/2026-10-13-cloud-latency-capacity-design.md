# 云同步时延、增量读取与安全归档设计

用户已于 2026-10-13 确认：保留密文历史与防重复证明；采用独立通知投递、增量同步、双方确认后的历史归档及缓存优先切页刷新。此次不改变布局、共享等级、计划须双人确认的业务规则。

## 平台约束与选择

推荐在现有协议上做兼容增量。只优化客户端无法解除推送等待和生命周期容量上限；整体替换云协议会扩大身份与数据迁移风险，未采用。

AGC CloudDB 触发器不能直接响应当前事务的 executeUpsert。依据 `docs/research/2026-10-13-agc-plan-dispatch.md`，新通道采用事务 outbox + 单条独立 wake insert + 专用数据库 worker，受实测闸门控制。默认保留同步 fallback，绝不使用裸 fire-and-forget。触发器实际自动调用和定时补送仍需用户云端验证。

## 1. 通知快路径

- 计划、不可变请求回执、outbox 在同一 CAS 事务提交。
- 生成稳定事件 ID，优先处理本次事件，避免旧队列先占据一次投递名额。
- 增加仅管理员可访问的 `PairPlanWake`。事务后等待单条 insert 的入库确认；唤醒数据包含事件 ID、创建时间和服务端 HMAC，不包含计划明文、Token 或服务密钥。
- 专用 `dateplanwake` 校验对象名、区名、签名并重读 outbox，再用现有 lease、状态版本、有效连接和通知开关校验发送。事件重复、延迟、乱序都不能绕过领取和完成状态。
- `FORTWO_PLAN_ASYNC_PUSH` 默认 false；云端实测自动触发和补送通过后才设 true。唤醒插入失败使用同步 fallback，不把已提交计划报为失败。
- TIMER worker 仍负责未发事件及过期 lease；补送未恢复是上线边界，不用代码测试冒充平台验收。

## 2. 版本增量同步与容量

- 增加 `PairPlanSyncState`（连接级序列/活动计数）、`PairPlanChange`（按序列读取的密文变化）、`PairPlanArchive`（最终密文记录）、`PairPlanArchiveVote`（成员对指定版本的归档确认）、`PairPlanReceiptArchive`（压缩回执与 digest）、`PairPlanEventArchive`（结束的投递审计）。
- 新模式由 `FORTWO_PLAN_STORAGE_V2` 控制，默认 false。密文协议不变；既有 `PairMemberBinding` 增补 `storageVersion`（默认 1）与 `cleanupPending`（默认 false），既有计划、回执、通知表增补查询索引。先部署兼容字段/索引与七个新增模型，再启用；首次在绑定 CAS 下初始化计数与变化序列。已迁移连接的版本为 2，即便关闭开关仍维持其归档与重试保护，不能回滚为旧版服务器。
- 活动计划仍最多 50 条；活动回执/事件保持原安全上限，但结束数据可分批迁出活动表，不把累计使用数当作终生上限。
- 新客户端读取有序变化页，每页最多 50 条；验证身份、会话、伴侣证明、版本与密文后落本机，再推进会话隔离游标。错误/崩溃不得跳过尚未落库的变化。旧读取入口保留兼容。
- 归档仅接受指定 planId/stateVersion，双方独立确认相同版本；客户端只提交已结束且没有改期待确认的计划，终态也要先同步给双方。服务器看不到结束时间，不上传明文时间来换取方便。
- 归档事务保留最终密文记录与幂等证明，活动表移除。旧请求先查原表/归档回执；旧 planId 查归档拒绝重建；不凭“列表没返回”删除本机历史或占用。
- 回执压缩归档仍保存原响应，解压有输出上限；通知终态归档保留审计，不删除正在等待或领取中的事件。
- 解除/清空必须分批涵盖新表；未完成清理不得谎报全部云数据已删除，保留原身份的补删凭据。

## 3. 客户端与页面刷新

- 页面切换先展示已有缓存，只为进入的可见页面读取当前版本；变化广播合并相同回合读取，旧异步完成不得覆盖较新的结果。
- 本机保存优先重算缓存，云快照按原健康/失败暂停规则合并发送；按需网络读取共享在途工作，不把成功结果作为永不失效的缓存。
- 共同计划待确认状态不触发无意义的空闲重算；确认/取消/时间变更才重算占用。
- 增量读取与归档后台收尾不阻塞本地保存/切页；写边界和解除重配仍使旧飞行结果失效。
- 记录固定阶段、请求次数及耗时，不记录身份、标题、时间、密文、Token、密钥或原始 SDK 错误。单元测试证明控制流，真实时延用设备/AGC 证据衡量。

## 4. 验证与交接

覆盖慢 provider、唤醒失败/重复/伪造、超过 50 个累计计划/200 个累计请求、归档版本竞争、离线重试、游标落库中断、跨会话晚到响应、切页刷新和旧协议兼容。执行云端 ES2020/ES5 strict 合同测试及客户端 offline/debug/release/ohosTest/perf 门禁。

源码同步到正式/隔离云工程，生成独立 worker 包并提供新增模型、环境变量、触发器和双端升级顺序。AI 不操作用户云端资源、凭据或设备数据；独立模式启用需要真实平台验收。
