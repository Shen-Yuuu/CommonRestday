# 真机反馈：角色统一、页头基线、排班安全区与邀请诊断

用户明确要求统一到已选 B 画风、角色底边与「共同休时」标题底部同线、修复排班 sheet 底部遮挡、排查真机发送邀请失败。

## 设计与修复边界

- 角色造型以当前已选合成图为唯一基准；用户随后明确：不需要保持原神态、动作，允许补出身体。此前改变脸型、眼睛和毛发感的稿已否定，未接入应用。用户确认新的三组动作校对稿造型一致后，衍生布布探头、休休探头和休休睡眠三张透明 PNG，替换旧 SVG 的正式引用；保留旧文件可回退。它们是统一静态素材，不是八套表情分层或完整互动动画。
- 页头改成上层「标题＋角色」底对齐、下层备注；角色内部绘制底对齐，缩放以底边为轴；固定角色槽不把动画值写回页面。网页同步构图，不让角色与「标题＋备注」整体居中。
- DayShiftSheet 内容滚动、保存操作独立底栏；用 SDK 核实的窗口导航避让区域与底部留白，不依赖某一台设备的小白条高度，背景可延伸但按钮不能进入手势区。
- 云链路保留原 requestId/密文、双人确认和未知结果语义。调查中发现 Gateway 多处 catch 吞掉阶段、UI 只给泛化反馈；新增白名单化诊断并让失败在表单/计划页可见，不输出标题、日程、配对 ID、Token 或 SDK 原始消息。修复可复现的恢复分支，但无真机日志前不宣称已确定远端根因。
- 不修改部署配置、证书、权限、版本号，不自动解除配对/清空请求，也不把未知结果当作成功或失败后新建计划。

用户确认使用当前项目新打的包，无法看日志。因此页面直接保留安全诊断阶段/错误码/数字 SDK 码/可选云诊断 UUID；不再要求用户必须提供日志，也不根据旧标题推定旧包。
