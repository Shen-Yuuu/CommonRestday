# 已发布测试版之后：Push 发布 Profile 是否需要重申请

核对日期：2026-10-19（Asia/Shanghai）。只读研究，没有修改发布签名、云端或业务代码。

## 已知条件

用户确认：计划邀请问题已解决；云端自动触发问题工单处理中；现已发布测试版本且使用正常。这里不能额外假定“使用正常”已包括锁屏、后台或进程结束后的离线 Push。

## 官方正文证据

通过隔离 `agent-browser` 会话，打开旧 `harmonyos-guides` 地址后等待文档动态渲染，成功读取正文；导航链接现指向新版 [开通推送服务](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/push-config-setting)，页面更新时间为 **2026-09-14 18:46**。网页搜索抓取最初只返回框架，不能据此说官方不存在该要求。

正文分别规定调试签名与发布签名。发布的条件是：申请发布证书，先确保推送服务已开通，再重新申请发布 Profile，完成手动签名。另将自分类权益申请作为独立步骤；不能把“申请工作提醒自分类通过”直接等同于“发布 Profile 已更新”。

官方 [发布应用的配置签名信息](https://developer.huawei.com/consumer/cn/doc/doccenter-deveco-studio/ide-publish-app#section945904791115) 说明工程需配置私钥 `.p12`、发布证书 `.cer` 和发布 Profile `.p7b`，然后构建携带发布签名的 APP。该页面同样已通过浏览器读到正文。

## 对本项目的精确判断

以下是根据官方前置条件作出的工程判断，不是官方逐字承诺“所有测试版都不需要更换 Profile”。

| 当前情况 | 应如何处理 |
| --- | --- |
| 现用发布 Profile 已在开通 Push 后生成，仍有效，应用／签名与所需能力匹配，并已用于当前测试版 | 不应仅因“测试版转正式版”或普通版本更新而要求重复申请。保留可用签名链，正常递增版本、构建、提审。 |
| Profile 是开通 Push 之前生成，或查明未包含所需能力 | 按官方流程重新申请对应发布 Profile，更新工程签名并重新构建。 |
| Profile／证书失效、签名信息或受控能力确实发生变化 | 根据实际变化更新相应签名材料；不是无条件重新创建所有证书。 |
| 仅确认排班、云配对、计划邀请／同步正常 | 这些不证明离线 Push 已验收，不应据此确认或否认 Profile。追加针对性测试即可，先不要盲目重申请。 |
| 同一发布测试包已验证锁屏、后台／进程结束后都能收到真实云 Push | 是该包 Push 链路可用的强证据，不应把重复申请 Profile 列成未完成事项；仍需保持下一包的签名与能力正确。 |

“离线 Push 没收到”也不自动证明 Profile 有错，还可能涉及用户通知开关、有效 Push Token、云消息投递、场景分类或设备状态。自动补送／唤醒触发器问题与客户端 Profile 配置是不同环节，工单处理中不应归因为重新签名即可解决。

建议仅向用户确认一个测试事实：**当前从测试渠道安装的包，在接收方锁屏／App 不在前台时，发起计划和确认计划是否都能收到通知，并正确打开对应计划？** 若已经做过，无需重复整套配置。

## 补充：非续期会员能力（本轮不作为主推方案）

已快速核实华为正式 [HarmonyOS 开发入门](https://developer.huawei.com/consumer/cn/develop-novice-guide/) 的商业模式部分列出四种商品，其中包含非续期订阅；正式 [消耗型／非消耗型／非续期订阅商品配置](https://developer.huawei.com/consumer/cn/doc/doccenter-distribution/games-center-non-subscription-0000002660208665)（更新 2026-10-14）确实存在“非续期订阅”类型。因此不能说平台只有永久买断与自动续费两种形态。

但本次没有完成普通工具应用一年有效期、到期权益与重复购买恢复的完整 API 行为验证，也未确认本账号商品开通资格。不要把它直接当作已可实施的一年会员产品。主方案如采用非消耗型 Pro 买断，无需为了这个候选项增加接入范围。

研究浏览器会话已关闭。本文未检查用户真实发布 Profile 的内部内容，也未读取私钥或发布后台；“当前不需要重申请”必须以表格中的实际条件为前提。
