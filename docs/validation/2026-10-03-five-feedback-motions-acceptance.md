## 实施结果

| 场景 | 实现与边界 |
| --- | --- |
| 展开今日安排 | 前三条常驻；剩余列表自然高度测量后局部展开/收起，箭头与高度使用相同进度；换向取消旧帧。不测量或改写标题高度。 |
| 分享等级 | 只对新选中项底色过渡 140ms，旧选中项立即撤去底色。文字、热区和存储行为保持。 |
| 保存计划 | 只在真实创建成功后发出计划 id，进入“共同 → 计划”并按排序定位。目标出现后一次性消费提示，保持约 800ms，240ms 恢复卡片底色。不迁移数据，不重排列表。 |
| 翻周 | 上周从左、下周从右进入 220ms；最新读数落地才进入，过期读数/动画不落地。导航不锁死，加载期间网格不接受旧数据操作。标题高度完全不参与。 |
| 手动同步 | 点击位置的原生按钮显示等待指示和“同步中…”，真实结果落到原位置；成功后仍可看到“已同步”。另一处入口禁用并发请求；错误仍只在我的页。没有计时假成功、进度百分比或新增云请求。 |

## 请用户运行新版核验

不必卸载或清空数据，直接从 DevEco 运行更新后的应用。以下每格仍为待设备：

1. 同休页“今天”至少有四条安排时：展开、收起各一次，检查额外列表不是突然整块出现；箭头与展开同步。连续快速点击三次，末态应与按钮文字一致；一至三条时不出现展开按钮。长名称/大字号不应被永久裁切。
2. 我的 → 伴侣与同步 → 分享哪些信息：依次切换三档。只观察新选中项底色过渡，旧项立即退出；再次点当前档不发动画/重复保存。退出并重进后选择保持；深浅模式也检查一次。
3. 从首页创建一条计划，再从共同页创建一条：成功后应进入“计划”，滚到对应真实标题与时间的条目；底色短暂强调后还原。故意只取消起草器，不应定位/高亮；保存失败也不应出现假的新条目。条目多于一屏时同样核验定位；返回其他页再进来不重播已消费的高亮。
4. 共同 → 周历及日程录入的周历：上一周、下一周、回本周；日期和网格按方向切换，主标题高度不变。连续快速翻三周，最终日期与日格一致，不能被旧周覆盖。滚动后切首页/我的，确认未重现标题闪烁；加载时箭头仍可点，网格暂不接受点击，数据落地后恢复。
5. 已配对时，用可恢复的网络断开制造一次同步失败，然后恢复网络。在我的页摘要或云配对弹层点手动重试：只该按钮出现等待指示，重复点不再发请求；成功变“已同步”并保留；若仍失败，应显示真实失败与可用重试入口，不改变本机数据。再制造一次失败，确认上次“已同步”不会阻止新重试。无需删除配对或改云端配额。
