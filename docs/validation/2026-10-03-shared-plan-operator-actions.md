# 共同计划与锁屏通知：需要用户操作的部分

更新：2026-10-04。现在不用清数据、不用卸载、不用解除已有配对。本轮不是“系统通知已接通”的交付。

> 第六批最新状态：无需用户部署或操作设备。本人冲突检查、v8 最小清理账及手动重试已过本机门禁，新开关继续关闭；剩余未知结果解析／正式 UI／Push 按开发顺序继续。下文为历史部署及后续账号准备清单，不要求现在重复已通过的探针。详见[第六批回执](./2026-10-04-shared-plan-conflict-cleanup.md)。

> 第二批历史进度：原身份／错误令牌／事务探针已按用户回执通过；其后隔离 dateplan 双端流程也由用户回报通过，不必重做。正式 App 和锁屏通知仍未接通；不要把历史部署步骤当作本批的立即操作要求。

## 一、现在可以先做：开通正式应用推送

1. 登录 AppGallery Connect，进入“开发与服务”，选择“两人份”的正式项目及应用。
2. 核对应用包名是 `com.common.fortwo`，不是之前的一次性 `com.common.fortwo.cloudspike`。
3. 进入“增长 → 推送服务”，点击“立即开通”。已开通则核对状态，不重复创建项目。
4. 在项目／应用对应的“开放能力管理”核对生效状态；官方配置指南提示生效可能需 5–10 分钟，以控制台实际显示为准。
5. 按实际用途申请自分类权益：双方主动发起的共同计划邀请、确认及状态更新。类别以控制台选项和审核为准，不为了绕额度填营销／紧急类别。
6. 核对推送与现有云服务的数据处理区域，当前路线按中国境内配置；不要为排错随意更换项目区域。
7. 告诉实施 AI：“推送服务状态、分类权益状态、后续测试是调试签名还是正式签名”。可以发遮挡敏感信息的状态截图，**不要发送 accessToken、Push token、服务账号私钥、证书密码或云端密钥**。

### 选择哪类及填写内容（2026-10-04）

只申请 **工作事项提醒**（`category=WORK`），不申请即时聊天（`IM`）。判据是业务用途，不是是否有两人互发通知；共同计划属于日程安排与待处理事项，不是聊天／私信。官方 [分类标准](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/push-apply-right) 有对应列，最终以华为审核为准。

消息内容示例：

```text
标题：共同计划待确认
正文：TA 发来一条共同计划邀请，请打开“两人份”查看并确认。

标题：共同计划已确认
正文：TA 已同意你的共同计划，请打开“两人份”查看。
```

备注：

```text
本应用用于两人日程协调。双方主动完成配对后，一方发送共同计划邀请，向另一方通知待确认事项；对方同意或拒绝后，向发起方通知处理结果。后续计划变更或取消也会发送状态通知。通知权限由用户授权，仅发送双方日程协作消息，不包含聊天、营销或广告，不向未配对用户发送。
```

这里描述拟上线的功能范围，不表示当前包已能发系统通知。配对不是通知授权，接入时仍要单独申请系统通知许可。

官方依据：[推送服务配置](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/push-config-setting)。开通不代表立即具备客户端功能，仍需 SDK、服务端发送和签名联调。

## 二、身份和事务探针就绪后再做

本轮已在 CloudDevSpikeOfficial 增加 **共同计划前置验证** 测试入口及云对象源码，客户端编译通过；尚未部署，没有真实云端证据。不要用正式“两人份”的“生成邀请码”按钮代替探针。

1. 使用已有 **CloudDevSpikeOfficial**，而不是 FortwoCloud。代码已放好，不用新建工程、不用复制文件。DevEco 若未显示新增文件，刷新对应工程目录；首页将有“共同计划前置验证”。
2. 在该隔离项目确认认证服务的匿名登录可用；此前匿名直连拒绝测试用的配置继续使用，不改正式应用认证配置。
3. 在 AGC“项目设置 → 常规／项目信息”取得隔离工程 **项目 ID**（不是应用 appId）。部署新增 **sharedplanpreflight** 云对象，依赖已安装。不要批量重部署其他函数。
4. 在新云对象对应函数的配置／环境变量中设置 `FORTWO_AUTH_PROJECT_ID` 为隔离项目 ID，`FORTWO_ENABLE_CAS_PROBE` 暂设 `false`。SDK 所需服务器凭据沿用平台安全配置；控制台保留 `AGC_`／`PROJECT_CREDENTIAL` 名称及前缀，不手动添加 AGC_CONFIG。若 SDK 认证失败，先定位平台凭据上下文；不把本地 Node 凭据文件用法照搬为控制台自定义变量。仅填项目 ID 不能替代 SDK 凭据。
5. 在两台可丢弃设备运行 **CloudDevSpikeOfficial 的 Application**，进入新页面，各点“1 · 验证匿名身份”。预期 `code=OK`、认证通过 true，两设备指纹不同。再点“2 · 验证错误令牌被拒绝”，预期 `AUTH_REJECTED`、false、空指纹。只发这些脱敏回包，不发令牌。
6. 用该 CloudProgram 的新对象定义部署 **PlanCasProbe**（只有 id/version/state/createdAt；客户端无读写权限）。在 AGC 云数据库增加独立存储区 **FortwoPlanProbe**，不要改／删除已有 FortwoSpike/FortwoPair 区，不覆盖现有默认 db-config。
7. 将探针函数环境变量 `FORTWO_ENABLE_CAS_PROBE` 改为 `true`，回测试页点“3 · 验证两个事务只能提交一个”。只需在一台设备点一次，云端会同时提交两个请求，无需人为同时点两台。
8. 通过回包必须同时满足：`code=OK`、`overlapObserved=true`、两腿均首读 1、一条 APPLIED／一条 NOT_COMMITTED、`finalVersion=2`，finalState 与胜者一致。按回包 probeId 在 **FortwoPlanProbe / PlanCasProbe** 查同一测试行核对；SDK_ERROR／RACE_INCONCLUSIVE 不能勾通过。
9. 给 AI 两台身份回包、错误令牌回包、事务回包及同一行控制台截图。测试完先把 `FORTWO_ENABLE_CAS_PROBE=false`；测试行可稍后明确授权清理，不与正式数据混删。
10. 两个真实门槛通过后，继续安全配对绑定及正式共同计划通道。现在新通知不会自动出现在正式“两人份”中，也不要求你解除已有配对。

错误项目／真正已撤销或过期令牌还需独立用例，不能把错误字符串拒绝当成这两项全已验证。部署若自动重新生成 PlanCasProbe.js，请核对字段和已提供模型一致。

匿名认证不要求用户看到华为账号登录页；旧会话安全升级另行设计，不能仅输入旧 pairId／uid 就认领身份。

1. 按提交的差异清单先部署新增模型和云对象，再部署兼容的新配对服务；核对已有云函数超时和区域设置。

3. 开通能力后检查签名 Profile 是否包含所需能力；调试包重新生成合适的自动签名，正式包重新申请／下载正式 Profile 并使用匹配证书。不能用 unsigned.hap 验证发布行为。
4. 安装到两台测试设备。现有老配对如何升级须有明确步骤，暂不要求你主动重配。
5. 推送通知权限由应用内专门入口申请，测试时允许；随后再测拒绝分支。
6. 新增隐私披露后，将 AGC 托管协议重新生成／发布，并检查正式 URL 内容；仓库 MD／HTML 修改不会自动更新托管页。

## 四、两台设备的最终测试顺序

以下只在实施 AI 明确宣布链路可测试以后操作：

1. A 发送邀请：A 显示等待 TA，B 计划页显示待我确认；两端空闲计算、今日安排、周历和系统日历均不因邀请改变。
2. B 切后台或正常划走，A 再发邀请；观察 B 系统通知。B 锁屏再测一次，观察通知是否符合设备设置。
3. 点击 B 通知，进入对应待确认卡；点同意，等待真实成功，核对两端相同时间和标题，只出现一份活动计划。
4. A 后台／锁屏时，B 同意新邀请；观察 A 确认通知，点击后到正确计划。
5. 尚未确认时打开计划 tab，圆点保留；处理完最后一条待确认，圆点消失。
6. B 离线点同意，不应提前占时间；联网手动重试后正确落地，不重复。
7. 按实施脚本测试 A 撤回与 B 同意竞争，只允许一个终态。
8. 拒绝通知权限后仍可同步和手动查看计划；免打扰／锁屏隐藏内容按系统设置验收，不把没响铃都判为应用故障。
9. 已确认后改期，未同意前旧时段仍有效；同意后才替换。两台设备系统日历授权分别确认，任何一方拒绝日历不影响共同计划。
10. 解除、清库、恢复、第三台身份和旧包兼容只在另行授权的可丢弃设备验证，不拿有价值数据的实例试删。
