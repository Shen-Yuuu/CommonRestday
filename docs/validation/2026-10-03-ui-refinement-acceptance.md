## 用户测试步骤（不需要重配对或清数据）

先在 DevEco 按通常方式运行最新包并保留数据，不卸载。以下是本批检查，不是让你执行 ohosTest 全量；后者仍按原隔离清单处理。

### A · 点击反馈

1. 首页静止时依次点共同→我的→同休，连续做 5 轮。应立即切页，只有按下项轻微缩放，不应旧/新两项同时暗闪。
2. 长按一个 Dock 项后移出取消，再单击。应恢复正常，不出现遗留按下态。再试系统减少动态效果。
3. 单击首页任一有结果的答案行，观察从按下到详情出现；应只有一次浅底反馈、一次详情。快速双击仍只开一个详情，关闭后另一条仍可打开。

### B · 今天安排

1. 用已有的班表与课程验证首页空闲摘要下出现当天安排；与班表录入页核对名称和时间。
2. 如需造数据，添加今天一条 09:00–11:00 的课程或适用的节次；过午夜夜班应保留昨天起点，带通勤的班次显示「班次·含通勤」，不是把含通勤时间说成班次核心时间。
3. 本机添加今天的计划，验证排序及莓粉计划标识。结束午夜应读 24:00，次日其他时间应明确「明天」。
4. 一天多于三条时默认三条，展开/收起可用，底部操作不遮挡。空日期不出现空时间轴，也不假造安排。新增测试数据可通过对应条目的正常删除入口清理，勿点清空全部。

### C · 我的与设置

1. 单人模式检查标题「单人模式」，副文案消失；整张伴侣/作息摘要卡均可点，原管理/设置文字按钮不再显示。
2. 伴侣详情检查两条短标题、按钮保持可用。已有配对不必解绑；共享选项不见 Radio/L 代号，点击选项只有该行选中，重开仍保持。
3. 若当前有同步错误，点首页“我的”页里的手动重试，应执行原重试，不顺便打开伴侣详情；必要错误和删除欠账提示仍保留。
4. 打开作息：约 38% 屏高，不再先进入查看/编辑二层卡；修改起床、就寝、准备分钟、往后计算、最短时段后保存，重开核对。再改一个值后取消/拖动关闭，应恢复上次保存值。
5. 错误时间或越界天数应提示而不保存；打开键盘、放大系统字体后正文仍可滚到全部字段和选项，保存/取消能触及、不被裁掉。

### D · 配色与粒子

1. 在日程录入周历查看普通计划并打开当天详情：不再以固定绿色表示计划；冲突仍是警示色。绿色自选班次不应被本批改成粉色。
2. 浅/深色各看 Dock 60 秒：出现位置和路径应变化，没有透明重置时的闪跳；点击落点不被装饰层截走。
3. 进班表栈页/录入 router 页再返回，或后台 10 秒再回来：应恢复粒子但没有叠起多组动画。开启减少动态效果，应只留静态光池；关闭后恢复。

若某项不符，发页面名称、浅/深色、系统字号、操作顺序和短录屏即可，不需要把两台配对机打回未配对。

## 2026-10-03 用户截图反馈：今日安排未显示

用户截图中摘要为“今天 2 段忙碌”，下方没有日程列表。本机复现确认是首页接线错误，而非展开按钮被隐藏：`nowEpochMin()` 的分钟值被传给接受毫秒值的 `todayEpochDay()`，把 2026-10-03 错读为 1970-01-01；查询结果为空时列表按原显示条件被隐藏。摘要走另一条正确读数，所以仍显示忙碌。

修复只将首页查询参数换成 `dayOfStart(now)`，沿用本次加载已经捕获的同一时刻。没有改布局、存储、日程或云请求逻辑，不需要重新录入数据。

回归证据：

- 首页接线检查不再只查“有没有调用”，改为检查分钟转当天的实际参数；旧代码执行时失败，修复后通过。
- 新增两例：2026-10-03 的两条真实日期安排能保留；23:59/00:00 两侧的夜班归日与昨晚/明天标签正确。
- 本轮命令 `node tools/verify.mjs --steps=offline,debug,release,ohostest`：ALL PASS / exit 0。离线 closed/open 两档均 286 passed / 0 failed、typecheck=0 errors；debug / release / ohosTest 均编译成功，WARN 为 287 / 287 / 267，与修复前一致，基线未修改；相关文件 `git diff --check` 通过。此前编译/模型用例通过未能证明首页日期接线正确，不能用来否定用户设备截图。

设备复验：从 DevEco 重新运行新包，保留已有数据，进入同休页。“今天”卡里应在共同空闲摘要下、底部两颗操作按钮上方看到当天安排；多于三条才出现展开按钮。本轮未操作模拟器，实际渲染仍待用户核验。
