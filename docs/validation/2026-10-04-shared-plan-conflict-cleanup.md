## 2. 已实现

### 2.1 日程冲突检查

`secureSharedPlans()` 装配真实安全 Gateway、RDB 持久化、本地检查器，构造不登录、不发请求。检查器从本人班次／循环／覆盖／课程／作息／计划读取，不直接信共同窗口缓存；展开范围带前一天，覆盖前一晚夜班、通勤与恢复。候选必须是未来且在本人当前计算视界内；读取失败不放行。

改期排除项必须同时匹配当前安全会话、actor、计划来源及 `shared:<pairId>:<planId>`，且在合并忙区间之前排除。相同时间的另一条个人计划、课程或班次仍阻断；不会按时间删除整个合并区间。没有可信身份映射，不取旧 TA 快照替新对方做承诺。对方同意时也必须重新检查对方本机输入。

重试仍使用原 requestId／原密文。原操作结果未知后若本机出现冲突，返回 `LOCAL_CONFLICT_RESULT_UNRESOLVED` 并保留请求，不再次发出可新增占用的操作、不假称取消。ACCEPT 新请求保存本地原候选供重试核对；旧请求仅在缓存版本仍一致时兼容读取，否则 `RETRY_REVIEW_REQUIRED`。这些状态目前还没有正式 UI；需后续只读请求回执解析，才能完整解除未知请求。

该检查是提交前的本地检查，不是跨设备锁；网络往返期间新增日程仍可能形成事后冲突，不承诺服务端锁住两端日程。

### 2.2 清空与云端清理

本地数据库升级为 v8，新增独立 `shared_pairing_cleanup`，只含 `flow_id/auth_uid/pair_id/status`。不保存 token、短码、证明、加密内容或私钥。配对进度 CAS 写入和 LIVE 候选登记同事务；清空将候选转为欠账并删除业务表，同一事务失败整体回滚。v7 的既有进度在清空前按原身份补登，破损进度／缺身份会留非授权的 REVIEW 提示；重复清空不覆盖旧账。

清空期间阻止新安全连接和新共同计划请求，清空前的异步 setup 操作由进程内代次及持久 CAS 作废。进程内代次不写入持久配对锚点，避免重启后合法进度无法恢复。未回包的创建／加入保留 UNRESOLVED，不为了删除调用 create/join，更不猜测“过期＝已经删除”。

清理表不参与业务清空。新连接在仍有清理事项时暂不允许创建／加入，防止补删误伤重新加入的旧 ACTIVE 会话。

原 SDK 身份必须现存且 UID 相符；不自动登录新身份。只有 `unpair` 返回 `OK + REVOKED` 并完成该记录的本地密钥清理才销账；网络未知或异常保留 WAITING，FORBIDDEN／NOT_FOUND／参数拒绝／超限清理要求留 REVIEW，而不是“删干净了”。

“我的 · 数据与隐私”显示欠账和手动重试。回前台最多处理两笔，进程内轮转、单飞；不建定时器、不加第二天同步逻辑。原身份丢失／恢复后的记录不会自动借用新身份。清空时及回前台尝试删除对应证明与配对别名，故障保留标识供后续清理；身份密钥未删除。

备份恢复将清理记录标为 RESTORED，暂停自动请求。旧备份无新清理表时，保留流程／已知会话编号的非授权提示，不从不可信恢复数据捏造登录能力。

## 4. 仍然不能开放发布的部分

1. 没有 pairId 的结果未知请求：待专用认证解析／清理入口，不能自动重复创建或加入来补删。原认证身份丢失、备份恢复记录也需可审计的处置路径。
2. 已确认／结果未知的计划重试：需要只读原 requestId 回执，冲突时不能靠再次 mutate 来“核实”。本批采取保留账、拒绝冒进，不代表这项已闭环。
3. 密钥衍生与清空交错时的未使用别名清扫、成功解绑后局部密钥删除失败的处置仍欠设备验证及完整扫尾。不能保证设备故障时 HUKS 别名一定消失。
4. 旧班表对方与新认证成员的可信对应、正式计划卡片／邀请／同意／改期／红点／未知结果提示还没接通。
5. Push 发送器、通知授权、token、未打开／锁屏投递、隐私披露及正式签名真机矩阵仍待后续。

结论：**本批为实现与本机门禁通过，不是新功能可启用、设备通过或 RELEASE READY。**
