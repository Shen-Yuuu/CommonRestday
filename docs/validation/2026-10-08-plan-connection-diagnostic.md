```text

错误码：RESULT_UNKNOWN · SDK 1008210009
```

示例不是本次设备实测结果。SDK 没有提供可读取的数字错误码时，不展示 SDK 数字，不猜测错误原因。

端侧日志标记为 `FORTWO_PLAN_LINK_DIAG`，诊断版本 `2026-10-08-diag1`，HiLog 标签为 `PlanConnection`。
这条日志在 DevEco 的设备日志中，不是 AGC 云函数日志。

日志只含固定的 tag、build、阶段、业务错误码及有界数字 SDK 码。不复制异常正文、堆栈、请求对象、认证 token、UID、密钥、伴侣凭证、短码或计划内容。
阶段和业务错误码通过固定名单，SDK 码仅允许最多 12 位数字（可带负号）；任意字符串错误字段不输出。
诊断信息只随本次结果返回，不写入连接凭据。

| 阶段前缀 | 含义与下一步定位方向 |
|---|---|
| `auth.*` | 主 App 配置读取、匿名认证初始化/登录/凭据获取；该阶段失败尚未走到计划云调用 |
| `key.*` | 设备密钥、原班表伴侣凭证或确认凭证；`key.agree/available` 可能发生在云回包之后 |

| `cloud.call` | 已到客户端调用 `dateplan` 的环节；不保证请求已通过网关或进入云对象 |
| `cloud.decode` / `reply.validate` | 客户端解析或校验回包 |
| `cloud.reply` | 已得到云端业务拒绝码，按该码核查云端配置/状态 |

## 用户操作

1. 用当前项目原有正确签名配置，重新 Build/Run **主 App CommonRestday**，覆盖安装。不要卸载、清数据或重新配对。
2. 打开「我的」→「伴侣与同步」→「共同计划连接」。
3. 若已有「操作结果待确认」等进度，点「检查连接 / 重试」；若仍是空态，点一次「生成短码」。等操作结束，不连续点击。
4. 将新增的「失败阶段」「错误码」两行截图发回；或在 DevEco HiLog 搜索 `FORTWO_PLAN_LINK_DIAG`，复制对应那一条诊断记录。
5. 若本次成功，回报成功即可，再按原流程连接另一台手机；无需人为制造失败。

本补丁不需要重新部署 ForTwoCloud / CloudDevSpikeOfficial，不需要更新云函数变量或更换证书，也不需要新增权限。
若 SDK 仍报签名/身份问题，须依据新证据单独处理；本次不提前改签名或降低鉴权。
