# 当前计划列表清理修复验证

## 原因与修复

此前只过滤 CANCELLED，WITHDRAWN 等已结束状态仍占据列表；本机和共同计划均未按结束时间过滤。

- 当前列表只显示尚未结束的本机计划，以及仍有有效时间内容的 PENDING / ACCEPTED 共同计划。
- `end <= nowEpochMin()` 时隐藏；正在进行、跨天尚未结束的计划保留。
- 撤回改期仅移除待确认修改，原已确认计划在结束前仍显示。原计划结束但有未来改期申请时仍保留申请，避免无法处理。
- 列表条数、空状态和待确认小圆点使用相同时间口径。
- 前台计划页每 30 秒检查一次当前分钟，只有可见条目改变才更新卡片数组；回到前台也进行本地过滤。组件卸载清理定时器。此检查不发云请求、不重算空闲。
- 云端记录、本机缓存、确认版本、日历历史、占用计算不删除或改写；未确定请求的「核实 / 重试」仍保留。

## 手机/模拟器复验

无需重新部署云函数。使用 DevEco 覆盖运行最新主项目，双端都更新客户端以应用新列表规则，不需要卸载或清数据。

1. 撤回未来待确认邀请：成功同步后，发起端卡片消失；另一端同步后也消失。
2. 打开有历史记录的计划页：已结束条目不显示；正在进行的条目继续显示。
3. 留在计划页等短计划结束：结束后下一次本地时间检查移除；回到前台立即重新过滤。
4. 对未来已确认计划申请改期再撤回：原计划仍显示，日程占用仍是原来的确认时间。
5. 检查全部条目隐藏后的空状态及待确认圆点；历史周历仍能查看原来的已确认安排。

本轮未操作真实设备、AGC 或模拟器 UI。上述设备交互是待用户复验项，离线测试与构建不等同于推送/云端联调验证。
