# 计划标题与冷启动同步验证

## 修改范围

### 计划类型与标题

固定类型（吃饭、看电影、散步、购物、出游）被选中时，标题立即替换为类型名称，即使此前手动改过标题。
选中「其他」保留当前标题，不清空、不替换；仍可继续手动修改。去掉过时的 titleTouched 闸门，增加索引范围校验，HTML 原型保持一致。空标题仍由现有草稿校验拦截。

### 冷启动更新

原初始化链包含网络快照拉取和重算；共同计划刷新、日历补清理等工作都等待整条链完成。

新初始化链只等待数据库、默认班次及偏好就绪：

1. 初次计算读取本机与已有伴侣缓存，广播页面更新，不等待网络。
2. 首次回前台的快照刷新和共同计划刷新分别从存储就绪链发起，不再串行等待快照再刷新计划。
3. 冷启动不重复排日切重算；未配对时不增加第二次快照刷新。温启动保留跨日重算行为。
4. 复用现有下拉刷新 single-flight、重算串行队列、会话/版本校验；通知授权、撤销检测、失败暂停和手动恢复规则不变。
5. 初始化失败时不执行依赖数据库的同步/清理，各分支捕获拒绝；不增加后台轮询，不自动重放待核实写请求。

本轮优化消除了客户端的串行阻塞，不等于云请求立即完成。认证、SDK 网络、云函数冷启动及设备性能仍可能带来等待。本轮未测量真实手机或模拟器端到端耗时。

## 设备复验建议

无需部署云端，双端覆盖运行最新主项目，不要卸载或清数据。

1. 打开创建计划弹窗：手改标题后选择看电影，标题应变为看电影；再选其他，标题仍为看电影；手填自定义标题后再选其他也不应清空。
2. 关闭 B 应用进程，在 A 修改班表及发起/确认计划并完成同步，然后冷启动 B。先看到缓存页面，班表和共同计划各自完成更新；计划刷新不应等待整轮班表同步结束。
3. 临时断网冷启动：旧缓存和已确认计划仍可查看，不出现空白闪动，不自动重发未确定请求。
4. 温启动同日、跨日分别验证；既有推送授权和配对撤销流程保持正常。

测试适配器证明的是生产代码调度关系；真机通知、AGC 运行和具体速度仍需按上述步骤复验。
