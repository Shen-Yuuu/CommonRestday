# 班表入口恢复与周历闪退修复验收

## 本次改动

- 「我的 → 班表与课程」恢复日程周历，可点日期编辑该日；第二个 Tab 为日程管理。
- 日程管理仅保留周班表、课程表。常用班次仍从周班表内进入。
- 保留按日期保存、多班次与分段排班的数据模型，不回退到旧循环序列，也不删除既有数据。
- 计算得到零个共同空闲窗口时，计算完成时间也会和缓存事务一起保存；不会再误报从未计算、显示 1 月 1 日。
- 共同页切换时安全读取滚动位置，并将空列表的 Scroll 绑定到对应控制器；保留切换动画和非空视图的滚动位置恢复。

## 故障证据与验证边界

只读检查当前模拟器既有的两份应用 JS 崩溃记录，异常为 `Cannot read property yOffset of undefined`，首个应用调用点为 `CoTimeView.commitView`。空列表未绑定控制器，切换时读取位置触发异常。安装的 API 26 SDK 声明明确说明未绑定 Scroller 的 currentOffset 可能返回 undefined；本次改用明确可空的 offset 并增加保护。

新增六项隔离回归：执行生产仓储验证旧窗口时间兼容、空结果时间、写入失败整批回滚、清空后的初始态及游标关闭；执行生产辅助函数及真实切换方法验证未绑定、异常、无效偏移和位置保留。页面入口接线也纳入静态回归。

未安装或启动测试版、未操作设备数据库、未清设备数据、未部署云端。离线控制器测试不是设备渲染与触摸测试。

`node tools/verify.mjs --steps=offline,debug` 全部通过：云关闭、开启两档各 365 项主测试通过，六项新增缓存／导航回归在两档均通过，类型检查 0 错误，Debug 构建成功。ArkTS 告警 281，未超基线 289。日志在项目上级 `.crdtest/verify-offline-closed.log`、`verify-offline-open.log`、`verify-debug.log`；本次涉及的已跟踪源码通过 `git diff --check`。

## 请在覆盖运行后复测

1. 不卸载、不清数据，覆盖运行主项目。打开「我的 → 班表与课程」，应先看到原日程周历。
2. 切到日程管理：仅有周班表、课程表；进入周班表，常用班次入口仍在，旧排班内容可读。
3. 在周班表添加一天的班次并保存，回首页。即使本次没有共同空闲窗口，也不应出现错误的 1 月 1 日计算提示；真正失败或过期的提示仍保留。
4. 共同页在空列表时切换「列表／周历／计划」，连续切换并返回，检查不闪退；再在有共同窗口的情况下重复。
5. 周历翻周、上下滚动、点日期打开明细；从我的班表点日期保存一个日程，检查周历与首页今日安排更新。
6. 有较长内容时滚动后切换 Tab 再返回，检查位置恢复和原切换动画。云配对、共同计划与已保存课程应保持不变。

无需重新部署云对象、重新申请权限或删除本机数据。
