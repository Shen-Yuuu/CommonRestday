# Feature Specification: 学生情侣双人共同时间闭环（M2.5 + 完整化）

**Created**: 2026-09-15  
**Status**: Approved（用户已授权免确认直通实施）  
**Input**: 基于 docs/ v1.1 修订版（大学生情侣一等场景、F2.0 本机代录配对、范围裁剪）实施 M2.5 双人闭环并完成首版功能闭环。

## Overview

在现有单机排班工具（M0–M2 已完成：领域引擎 + 四种录入 + 数据层）基础上，打通产品核心差异化价值：**双人共同空闲时间的计算、展示与计划闭环**。首选场景为大学生情侣——两人分属不同专业，在同一台手机上分别导入/录入各自课表（或班表），App 立即算出扣除睡眠/通勤/收整缓冲后的"真正可用"共同时间窗口（含共同自习标签），可从窗口一键创建共同计划；任一方修改课表后自动重算并对冲突计划给出替代窗口。云端配对作为增强路径（AGC 就绪后生效，未就绪自动降级为本机代录，不阻塞任何功能）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 本机代录双课表，算出共同窗口（Priority: P1）🎯 MVP

小夏和男友分属不同专业。小夏在自己的手机上：通过"添加伴侣"建立本机伴侣档案，为男友导入他的课表（粘贴文本/手动添加，与自己的导入体验完全一致）。保存后打开"共同时间"页，看到未来视界内两人都空闲的时间窗口列表，可按标签筛选（≥2h/半天/完整同休日/共同周末/共同自习/旅行），其中工作日白天 ≥2h 的窗口带"共同自习"标签。

**Why this priority**: 这是产品北极星指标（查看共同窗口 → 创建计划）的前提链路，也是用户想法的核心诉求；引擎已支持双输入，本故事完成"最后一公里"接线。

**Independent Test**: 录入两份含单双周差异的课表后，共同时间页出现非空窗口列表；删除伴侣数据后回到单人语义。

**Acceptance Scenarios**:

1. **Given** 已有"我"的课表，**When** 添加伴侣并导入第二份课表（课程时间与我有部分交叠），**Then** 共同时间页的窗口排除双方课程时段、双方夜间睡眠时段与收整缓冲。
2. **Given** 双份课表中我周一 1-2 节有课、伴侣周一全天空闲，**When** 查看周一窗口，**Then** 上午 8:00 前后的窗口不出现"共同自习"标签冲突（窗口起点晚于我的下课+收整）。
3. **Given** 伴侣课表含"1-16 周单周"课程，**When** 展开计算，**Then** 单周/双周的正确日期产生/不产生忙碌块。
4. **Given** 无伴侣数据，**When** 打开共同时间页，**Then** 显示"我的空闲"语义与添加伴侣引导，无崩溃。

---

### User Story 2 - 引擎参数可配置且真实生效（Priority: P1）

小夏夜班实习下班后需要 6 小时恢复；男友习惯晚睡。两人在"我的"页分别调整自己的起床/就寝时间、收整缓冲，保存后回到首页，今晚的可用时长随之变化。

**Why this priority**: 产品原则第 1 条（"算的是可用"）依赖用户可校准参数；当前代码硬用默认值，是已确认的断链缺陷。

**Independent Test**: 修改就寝时间 22:30→23:30 保存，首页"今晚"卡片可用时长 +1h。

**Acceptance Scenarios**:

1. **Given** 默认就寝 22:30，**When** 在设置中改为 23:30 并保存，**Then** 参数持久化，重算后当晚窗口结束时刻为 23:30。
2. **Given** 伴侣档案已建立，**When** 修改伴侣参数，**Then** 仅伴侣侧的作息参与计算，我的参数不受影响。

---

### User Story 3 - 首页"我们"模式三卡（Priority: P1）

已录入双方课表后，首页三卡展示真正的共同语义：今晚剩余共同空闲时长、距离下一个完整同休日天数、视界内最长出行窗口。

**Why this priority**: 首页是"先给答案"原则的落点；无伴侣时展示"我的空闲"语义与配对引导。

**Independent Test**: 双份课表录入后首页三卡数值来自共同窗口缓存；删除伴侣后回退单人语义。

**Acceptance Scenarios**:

1. **Given** 双方课表已录入且已重算，**When** 进入首页，**Then** 三卡分别显示今晚共同空闲、下个完整同休日倒计时、最长出行窗口。
2. **Given** 未配对，**When** 进入首页，**Then** 显示"我的空闲"三卡 + "添加伴侣"引导卡。

---

### User Story 4 - 首启隐私弹窗与隐私等级切换（Priority: P1）

首次启动弹出隐私政策弹窗（同意后不再出现）；"我的"页可在 L1/L2/L3 之间切换共享等级，切换后持久化并参与快照生成。

**Why this priority**: 隐私弹窗是上架合规硬门槛；等级切换是产品信任设计的用户侧入口（存储与领域侧已就绪）。

**Independent Test**: 清除应用数据后首次启动出现弹窗；切换等级后重启 App 仍保持所选等级。

**Acceptance Scenarios**:

1. **Given** 首次启动，**When** 进入首页，**Then** 弹出隐私政策弹窗；拒绝则退出，同意后持久化标记并不再弹出。
2. **Given** 已进入 App，**When** 在我的页把共享等级从 L2 切到 L1，**Then** 等级持久化，页面说明随等级变化。

---

### User Story 5 - 从窗口创建共同计划（Priority: P2）

小夏在共同时间页点开一个周六窗口，创建"一起看电影"计划：起止时间被硬限制在窗口内，保存后计划出现在"计划"Tab 列表，且该时段在后续计算中占用忙碌时间。

**Why this priority**: 计划是"窗口 → 行动"的转化出口（北极星指标的分母→分子）。

**Independent Test**: 创建计划后计划列表可见该条目；再次进入窗口列表时该时段已从空闲中扣除。

**Acceptance Scenarios**:

1. **Given** 一个 15:00–22:30 的窗口，**When** 创建 19:00–21:30 的计划，**Then** 保存成功，计划列表显示，重算后 19:00–21:30 变为忙碌。
2. **Given** 计划列表中有一条计划，**When** 点击取消并确认，**Then** 计划从活跃列表移除，该时段恢复空闲。
3. **Given** 日历权限被拒绝，**When** 创建计划，**Then** 计划仍创建成功（仅本地），提示可用 App 内提醒。

---

### User Story 6 - 改课表自动重算与冲突提示（Priority: P2）

男友临时加了一门周一晚上的课，与已有的"周一一起自习"计划冲突。保存课表后系统自动重算，计划页该计划标红显示冲突，并推荐时长最接近的后续共同窗口作为替代。

**Why this priority**: "班次变化自动重算+冲突提示"是 PRD F7 承诺的长期价值；当前重算仅进首页触发，是已确认断链。

**Independent Test**: 修改任一方课表保存后无需手动刷新，共同窗口缓存即更新；制造一个与计划交叠的改动，计划状态变为冲突且附替代窗口。

**Acceptance Scenarios**:

1. **Given** 存在计划 P（19:00–21:30）且无冲突，**When** 为"我"添加一门覆盖 19:30–21:00 的课，**Then** 重算后 P 状态为冲突，并展示 ≥1 个替代窗口（若存在）。
2. **Given** 无任何计划，**When** 修改课表，**Then** 静默重算成功，无异常提示。
3. **Given** 涂抹/编辑班次/导入课程的任一保存动作，**When** 保存完成，**Then** 自动触发重算（无需进入首页）。

---

### User Story 7 - 2×2 桌面服务卡片（Priority: P3）

添加 2×2 桌面卡片，常驻显示"距下次共同休息还有 N 天"与次窗口摘要，点击跳转首页；未配对时显示"我的下次休息"。

**Why this priority**: PRD F8 P0 项；卡片读计算缓存，杀进程后仍显示最后结果。

**Independent Test**: 添加卡片后修改班表，卡片倒计时随重算结果变化。

**Acceptance Scenarios**:

1. **Given** 已有共同窗口缓存，**When** 桌面添加 2×2 卡片，**Then** 卡片显示倒计时天数与次窗口摘要。
2. **Given** 杀掉 App 进程，**When** 查看卡片，**Then** 仍显示最后计算结果。

---

### User Story 8 - 计划本地通知提醒（Priority: P3）

计划确认后引导开启通知，注册出发前本地提醒；取消计划时同步取消提醒。

**Why this priority**: PRD F10 P0 本地通知的最低可用集；权限被拒时静默降级为 App 内提醒。

**Independent Test**: 创建计划后通知中心出现授权引导；授权后到点收到提醒。

**Acceptance Scenarios**:

1. **Given** 通知权限已授予，**When** 创建带提醒的计划，**Then** 出发前收到本地通知。
2. **Given** 通知权限被拒绝，**When** 创建计划，**Then** 计划正常创建，无崩溃，仅无系统通知。

---

### User Story 9 - 云端配对封装（增强路径，Priority: P3）

"添加伴侣"页提供云端配对入口：生成 6 位邀请码；AGC 未配置/无华为账号登录时入口降级提示并引导本机代录。云函数调用代码就绪但 AGC 开通为账号侧前置条件。

**Why this priority**: 满足异地双设备场景；因外部依赖不可控，列 P3 且不阻塞任何本机功能。

**Independent Test**: 未配置 AGC 时点击云端配对，得到明确的降级提示而非崩溃；本机代录全流程不受影响。

**Acceptance Scenarios**:

1. **Given** AGC 未配置，**When** 打开云端配对入口，**Then** 显示"云端服务未就绪，已为您切换本机代录模式"类提示，功能可用。
2. **Given** 任何网络状态，**When** 使用本机代录全部功能，**Then** 100% 可用，无网络请求。

---

### Edge Cases

- 双方课表完全交叠（无任何共同窗口）→ 共同时间页显示空态与调整建议（检查课表/放宽参数），不崩溃。
- 视界内全程忙碌 → 首页出行卡显示"暂无窗口"占位而非空白。
- 伴侣档案存在但课表为空 → 视为全闲参与计算（与"我"无班表时一致），首页提示"伴侣课表未录入"。
- 删除伴侣档案 → 级联清除 owner=PARTNER 的全部班表数据与伴侣参数，回退单人模式并重算。
- 计划创建时间超出窗口边界（拖拽/步进越界）→ UI 层硬限制，不可保存。
- 学期锚点未设置时导入课程 → 引导先设置学期锚点（沿用现有行为）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持在本机为"我"和"伴侣"分别维护班表数据（班次类型/循环模板/涂抹覆盖/课程），数据以 owner 维度隔离存储。
- **FR-002**: 系统 MUST 在已存在伴侣数据时，用"我的班表+我的参数"与"伴侣班表+伴侣参数"分别构建忙区间后计算共同空闲窗口。
- **FR-003**: 窗口分类 MUST 包含 STUDY 标签：≥2h 且落在周一至周五 08:00–21:00 内。
- **FR-004**: 系统 MUST 提供共同时间页：窗口列表 + 标签筛选（≥2h/半天/完整同休日/共同周末/共同自习/过夜旅行/短途旅行）。
- **FR-005**: 引擎参数（起床/就寝/收整缓冲/视界天数）MUST 可由用户在 UI 修改、持久化并真实参与计算；伴侣参数独立于我的参数。
- **FR-006**: 首页三卡 MUST 在有伴侣数据时展示共同语义，无伴侣时展示"我的空闲"语义与添加伴侣引导。
- **FR-007**: 首次启动 MUST 展示隐私政策弹窗，同意后持久化标记；拒绝则不进入应用。
- **FR-008**: 隐私共享等级（L1/L2/L3）MUST 可在 UI 切换并持久化。
- **FR-009**: 用户 MUST 能从任意窗口创建共同计划，计划起止硬限制在窗口内；计划创建/取消后 MUST 触发重算（计划占用忙碌时间）。
- **FR-010**: 计划列表 MUST 展示状态（正常/冲突/已取消），取消需确认。
- **FR-011**: 任一班表/课程/参数修改保存后 MUST 自动触发重算（事件驱动，无需进入首页）。
- **FR-012**: 重算后系统 MUST 对每个活跃计划执行冲突检测（排除自身占用的交叠判定），冲突计划标红并推荐时长最接近的替代窗口（存在时）。
- **FR-013**: 系统 MUST 提供 2×2 桌面服务卡片，读计算缓存渲染倒计时与次窗口摘要，支持点击跳转。
- **FR-014**: 系统 MUST 在计划确认后尝试注册本地出发提醒（通知权限拒绝时静默降级）。
- **FR-015**: 云端配对入口 MUST 在 AGC 未就绪时优雅降级（提示 + 引导本机代录），不得影响本机功能与稳定性。
- **FR-016**: 删除伴侣档案 MUST 级联清除伴侣全部数据并回退单人模式。
- **FR-017**: 日历写入（Calendar Kit）MUST 在权限授予时把计划写入"同休日"专属日历，权限拒绝时计划仍创建（仅本地），取消计划时级联删除日历事件。
- **FR-018**: term_config 中的节次作息模板 MUST 真实读取参与课程展开（修复"存而不读"断链）；班次类型编辑 MUST 暴露夜班强制开关（nightMode）。

### Key Entities *(include if feature involves data)*

- **Owner（ME | PARTNER）**: 班表数据的归属维度，本机代录双人模式的隔离键。
- **伴侣档案（PartnerProfile）**: 伴侣昵称 + 伴侣引擎参数（起床/就寝/收整）+ 存在标记，存储于 Preferences。
- **共同计划（Plan）**: 标题/类型/起止（epochMin）/状态（OK/CONFLICT/CANCELLED）/替代窗口建议；本机代录模式下由创建方设备持有。
- **窗口标签（WindowTag）**: MEAL/HALF_DAY/FULL_DAY/TWO_DAYS/WEEKEND/OVERNIGHT_TRIP/TRIP/STUDY。
- **冲突检测结果（ConflictResult）**: 计划 + 是否冲突 + 替代窗口（可选），重算后持久化到计划状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 两份含单双周差异的课表录入后，1 次重算（<200ms 本地）产出正确共同窗口，PRD F4 夜班示例回归断言不破坏。
- **SC-002**: 全部既有 49 个领域单测 + 新增用例（STUDY/伴侣装配/冲突检测）100% 通过，domain 层保持零 Kit 依赖。
- **SC-003**: 每个用户故事对应的页面路径可独立走通（录入→计算→展示→计划→冲突）。
- **SC-004**: 构建零 error；AGC 未配置时应用无崩溃、无功能残废。

## Assumptions

- 首版双方同一时区（v1.1 决策 D8），所有计算基于设备本地时区 epochDay/epochMin。
- AGC 云函数/账号/签名未开通；云端配对只交付端侧调用封装与降级路径，真机双机联调延后。
- 桌面卡片只交付 2×2 规格（2×4 为 P1）。
- 实况窗、Push、OneHop、二维码扫码、班表网格 OCR 均不在本特性范围。
- 本机代录模式下隐私等级仅影响快照生成与未来的对方可见渲染，本机展示双方完整数据（数据所有者本人在操作）。
- 现有工程为分层 HAR 架构（entry/feature/domain/data/cloud/commons），状态管理沿用 V2 装饰器模式，不做架构迁移。
